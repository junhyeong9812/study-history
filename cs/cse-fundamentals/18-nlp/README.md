## 1. 출발점: 왜 언어가 어려운 문제인가

### 1.1 자연어의 본질적 어려움

```
컴퓨터에게 자연어가 어려운 이유:

  (1) 모호성 (Ambiguity):
      "배가 아프다" → 과일? 복부? 선박?
      문맥 없이는 결정 불가.

  (2) 가변성: 같은 뜻을 무한한 방식으로 표현 가능.
      "비가 온다" = "하늘에서 물이 떨어진다" = "우천이다"

  (3) 맥락 의존성: 의미가 주변 문맥에 의해 결정.
      "그 사과를 먹었다" → "그"가 가리키는 대상은? → 이전 문장에 있다.

  (4) 세계 지식: 언어 이해에 상식이 필요.
      "존이 벽돌을 떨어뜨려 유리가 깨졌다"
      → 벽돌이 유리보다 단단하다는 물리 상식이 필요.

  → 컴퓨터에게 "언어를 이해시키는 것"은 AI의 가장 어려운 과제 중 하나였다.
  → 그런데 Transformer/LLM이 놀라운 진전을 이루었다.
```

### 1.2 NLP의 발전 흐름

```
  규칙 기반 (1950s~80s)
    → 사람이 문법 규칙을 수동으로 작성. 한계 명확.
  
  통계 기반 (1990s~2000s)
    → 대량의 데이터에서 확률적 패턴 학습. N-gram, HMM, CRF.
  
  신경망 기반 (2010s)
    → Word2Vec, RNN, LSTM. 분산 표현의 힘.
  
  Transformer/LLM (2017~현재)
    → Attention Is All You Need. BERT, GPT. 패러다임 전환.
    → 규모(scale)가 핵심: 더 큰 모델 + 더 많은 데이터 = 더 나은 성능.
```

## 2. 텍스트 전처리 — 컴퓨터가 읽을 수 있게

### 2.1 토크나이징 — 왜 단어 단위로 쪼개는가

```
🔴 토크나이징: 텍스트를 "토큰" 단위로 분할.

  "I love NLP!" → ["I", "love", "NLP", "!"]

왜 필요한가:
  컴퓨터는 문자열을 직접 이해하지 못한다.
  의미의 기본 단위(토큰)로 쪼개야 벡터로 변환할 수 있다.

세 가지 수준:

  단어 수준: "I", "love", "NLP"
    문제: 어휘 크기가 매우 큼. 모르는 단어(OOV) 처리 불가.
    "unfriendly" → 어휘에 없으면? → <UNK>

  문자 수준: "I", " ", "l", "o", "v", "e", ...
    문제: 시퀀스가 너무 길어짐. 의미를 담기 어려움.

  🔴 서브워드 수준 (현대 표준): BPE, WordPiece, SentencePiece
    "unfriendly" → ["un", "friend", "ly"]
    
    왜 이것이 최선인가:
      자주 나오는 단어: 통째로 하나의 토큰 ("the", "is")
      드문 단어: 서브워드로 분해 ("un" + "friend" + "ly")
      → OOV 문제 해결 + 어휘 크기 적당 (보통 30K~50K)
      → 형태론적 정보도 포착 ("un-" = 부정, "-ly" = 부사)

  BPE (Byte Pair Encoding)의 원리:
    (1) 모든 문자를 초기 어휘에 넣는다
    (2) 가장 빈번한 문자 쌍을 합쳐서 새 토큰으로 추가
    (3) 원하는 어휘 크기가 될 때까지 반복
    
    → 데이터에서 빈도 기반으로 자동으로 서브워드를 학습!
    → GPT, BERT 등 대부분의 LLM이 BPE 변형을 사용.
```

## 3. 단어 표현 — 숫자로 의미를 담기

### 3.1 원핫 인코딩 — 왜 이것으로는 부족한가

```
  어휘 = ["cat", "dog", "fish", ...]  (|V| = 10,000)
  
  cat  = [1, 0, 0, ..., 0]  (10,000차원)
  dog  = [0, 1, 0, ..., 0]
  fish = [0, 0, 1, ..., 0]

문제:
  (1) 모든 단어 쌍의 거리가 동일: cat과 dog의 거리 = cat과 fish의 거리
      → 의미적 유사성을 전혀 포착하지 못한다!
  (2) 차원이 너무 높음: 10,000차원 → 메모리 낭비
  (3) 희소(sparse): 거의 모든 원소가 0
```

### 3.2 분산 표현 — 왜 "밀집 벡터"가 의미를 담는가

```
🔴 [핵심 아이디어] 분포 가설 (Distributional Hypothesis):
  "비슷한 문맥에서 나타나는 단어는 비슷한 의미를 가진다."
  — J.R. Firth: "You shall know a word by the company it keeps."

  "나는 __을 먹었다" → 사과, 밥, 빵, 고기 → 비슷한 의미 (음식)
  같은 빈칸에 들어갈 수 있는 단어들은 의미가 비슷하다!

  → 문맥 패턴을 벡터로 인코딩하면, 비슷한 단어가 비슷한 벡터를 갖게 된다.
```

### 3.3 Word2Vec — 왜 이것이 혁명적이었는가

```
🔴 [모델] Word2Vec (Mikolov et al., 2013):
  신경망으로 단어 벡터를 학습한다.

  Skip-gram: 중심 단어로 주변 단어를 예측
    "the cat sat on the mat"
    중심: "sat" → 예측: "cat", "on" (주변 단어)

  CBOW: 주변 단어로 중심 단어를 예측 (Skip-gram의 반대)

  학습 결과: 각 단어가 100~300차원의 밀집 벡터를 가짐.

왜 혁명적이었는가:

  벡터 연산으로 의미를 포착!
  
  king - man + woman ≈ queen
  paris - france + japan ≈ tokyo
  
  벡터 공간에서 "남성→여성" 방향, "나라→수도" 방향이 일관되게 나타난다!
  → 의미적 관계가 벡터 산술로 표현된다
  → Ch.02 선형대수의 벡터 연산이 "의미"를 다루게 된 것!

  코사인 유사도 (Ch.02):
    cos(king, queen) > cos(king, apple)
    → 의미적으로 가까운 단어의 벡터 방향이 비슷하다
```

### 3.4 한계 — 왜 문맥이 필요한가

```
Word2Vec의 한계:
  각 단어에 "하나의 벡터"만 부여.
  
  "bank"의 두 가지 의미:
    "I went to the bank to deposit money" (은행)
    "I sat on the bank of the river" (강둑)
  
  같은 벡터로 표현! → 다의어(polysemy) 처리 불가.
  
  → 해결: 문맥에 따라 벡터가 달라지는 모델 (ELMo, BERT, GPT)
    → "문맥화된 임베딩(contextualized embedding)"
```

## 4. 순차 모델 — RNN, LSTM, GRU

### 4.1 RNN — 왜 "순환"인가

```
🔴 [아이디어] 순서가 있는 데이터(텍스트, 시계열)를 처리하려면:
  이전 단어의 정보를 "기억"하면서 다음 단어를 처리해야 한다.

  RNN: 은닉 상태(hidden state)를 통해 이전 정보를 다음 단계로 전달.

  h_t = f(W_h · h_{t-1} + W_x · x_t + b)

  h_t: 시각 t의 은닉 상태 ("지금까지의 기억")
  x_t: 시각 t의 입력 (현재 단어 벡터)
  W: 가중치 행렬 (학습)

  시각화:
    x₁ → [RNN] → h₁ → [RNN] → h₂ → [RNN] → h₃ → 출력
           ↑              ↑              ↑
        (이전 h를 다음에 전달 = "순환")

문제: 장기 의존성 (Long-term Dependency)
  "The cat, which was sitting on the mat in the corner of the room, was ..."
  
  "was"의 주어가 "cat"임을 알려면 → 많은 단어를 건너서 기억해야 함.
  RNN은 긴 시퀀스에서 초기 정보가 사라진다 (기울기 소실 문제).
  
  왜 사라지는가:
    역전파에서 그래디언트가 시간 단계마다 곱해진다.
    |곱해지는 값| < 1이면 → 기하급수적으로 작아짐 (소실)
    |곱해지는 값| > 1이면 → 기하급수적으로 커짐 (폭발)
    
    → Ch.01 연쇄법칙의 반복 적용에서 오는 문제!
```

### 4.2 LSTM — 기울기 소실을 어떻게 해결하는가

```
🔴 [핵심 아이디어] "게이트(gate)"로 정보의 흐름을 제어한다.

  세 개의 게이트:
    Forget gate:  이전 기억 중 얼마나 "잊을 것인가"
    Input gate:   새 정보 중 얼마나 "기억할 것인가"
    Output gate:  현재 기억 중 얼마나 "출력할 것인가"

  셀 상태(Cell State): 정보가 "고속도로"처럼 직접 흐른다.
    → 기울기가 곱셈 대신 덧셈으로 전달 → 소실 문제 완화!

  왜 "게이트"인가:
    시그모이드 함수 σ(x): 출력이 0~1 → "문의 열린 정도"
    σ = 0: 완전히 닫힘 (정보 차단)
    σ = 1: 완전히 열림 (정보 통과)
    → 네트워크가 학습을 통해 "무엇을 기억하고 무엇을 잊을지" 자동으로 결정!

🔴 GRU (Gated Recurrent Unit):
  LSTM의 간소화 버전. 게이트를 2개로 줄임 (Reset, Update).
  성능은 비슷하면서 파라미터가 적다 → 더 빠른 학습.
```

## 5. Attention — "모든 것에 동등하게 집중하지 않는다"

### 5.1 왜 Attention이 필요한가

```
RNN/LSTM의 또 다른 한계:
  전체 입력 시퀀스를 하나의 고정 크기 벡터(마지막 은닉 상태)로 압축.
  긴 문장이면 → 앞부분 정보가 손실!

🔴 Attention의 핵심 아이디어:
  "출력의 각 부분을 생성할 때, 입력의 어떤 부분에 집중할지 가중치를 계산한다."

  번역 예시: "I love NLP" → "나는 NLP를 좋아한다"
  
  "좋아한다"를 생성할 때:
    "I"에 0.1, "love"에 0.8, "NLP"에 0.1의 가중치 → "love"에 집중!
  "NLP를"을 생성할 때:
    "I"에 0.1, "love"에 0.1, "NLP"에 0.8 → "NLP"에 집중!

  가중치 = "이 출력을 만들 때 이 입력이 얼마나 관련 있는가"
  → 동적으로 계산 → 각 출력 위치마다 다른 입력 부분에 집중
```

### 5.2 Self-Attention — Transformer의 핵심

```
🔴 [정의] Self-Attention:
  시퀀스의 각 위치가 같은 시퀀스의 모든 다른 위치와의 관계를 계산.

  "The cat sat on the mat because it was tired"
  "it"이 무엇을 가리키는가? → "cat"과의 attention 가중치가 높아야!

  수식:
    Q = XW_Q  (Query: "무엇을 찾고 있는가")
    K = XW_K  (Key: "내가 가진 정보의 라벨")
    V = XW_V  (Value: "실제 전달할 정보")

    Attention(Q, K, V) = softmax(QK^T / √d_k) · V

  왜 Q, K, V인가:
    검색 비유:
      Q = 검색어 ("고양이와 관련된 단어 찾기")
      K = 각 문서의 제목 (문서마다 "나는 이런 내용이야")
      V = 각 문서의 내용 (실제 전달할 정보)
      
      QK^T = 검색어와 각 제목의 관련도 점수
      softmax = 점수를 확률로 변환
      × V = 관련도에 따라 가중 합산 → 필요한 정보 추출

  왜 √d_k로 나누는가:
    QK^T의 값이 d_k가 크면 커진다.
    softmax에 큰 값이 들어가면 → 거의 원핫이 됨 → 그래디언트가 사라짐.
    √d_k로 나누면 → 값의 스케일을 적절히 유지.
    🟢 이것은 내적의 분산이 d_k에 비례하므로, √d_k로 정규화하여 분산을 1로 맞추는 것.

Multi-Head Attention:
  여러 "관점"에서 동시에 attention을 계산.
  
  왜: 하나의 attention은 하나의 관계 유형만 포착.
    Head 1: 문법적 관계 ("주어-동사")
    Head 2: 의미적 관계 ("대명사-선행사")
    Head 3: 위치적 관계 ("인접한 단어")
    → 여러 관계를 동시에 포착!
```

## 6. Transformer — "Attention Is All You Need"

### 6.1 왜 Transformer가 RNN을 대체했는가

```
🔴 RNN의 근본적 한계:
  순차 처리 — t번째를 계산하려면 t-1번째가 필요.
  → 병렬화 불가능! GPU의 수천 코어를 활용할 수 없다.

  Transformer의 혁신:
  Self-Attention은 모든 위치를 동시에 처리!
  → 완전 병렬화 가능 → GPU에서 극적으로 빠른 학습.

  ┌──────────────┬────────────┬────────────┐
  │ 비교          │ RNN/LSTM   │ Transformer│
  ├──────────────┼────────────┼────────────┤
  │ 시퀀스 처리   │ 순차적      │ 병렬       │
  │ 장거리 의존성  │ 어려움      │ 직접 연결   │
  │ 학습 속도     │ 느림        │ 빠름       │
  │ GPU 활용     │ 비효율      │ 최적       │
  │ 메모리        │ O(n)       │ O(n²)     │
  └──────────────┴────────────┴────────────┘

  Transformer의 대가: 메모리 O(n²)
    모든 위치 쌍의 attention을 계산 → n²개의 점수.
    n = 10,000이면 → 1억 개의 점수 → 긴 시퀀스에서 메모리 병목.
    → 해결 시도: Sparse Attention, Linear Attention, FlashAttention 등.
```

### 6.2 Transformer 구조

```
🔴 인코더-디코더 구조 (원래 논문):

  인코더 (Encoder): 입력 시퀀스를 표현으로 변환
    [Self-Attention] → [Feed-Forward] → ... (N번 반복)
  
  디코더 (Decoder): 표현으로부터 출력 시퀀스를 생성
    [Masked Self-Attention] → [Cross-Attention] → [Feed-Forward] → ... (N번)
    
    Masked: 미래 위치를 보지 못하게 마스킹 (왼쪽→오른쪽 생성이므로)
    Cross-Attention: 디코더가 인코더의 출력에 attention

  Positional Encoding: 왜 필요한가?
    Self-Attention은 순서 정보가 없다! (집합 연산에 가까움)
    "cat sat"과 "sat cat"을 구별할 수 없다.
    → 각 위치에 고유한 벡터를 더해서 순서 정보를 주입.
    
    sin/cos 함수 사용:
      PE(pos, 2i) = sin(pos / 10000^(2i/d))
      PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
      
      왜 sin/cos: 상대적 위치를 선형 변환으로 표현 가능.
```

## 7. 사전학습 모델 — BERT와 GPT

### 7.1 사전학습이란 — 왜 이것이 패러다임을 바꿨는가

```
🔴 [핵심 아이디어]
  대규모 텍스트(위키피디아, 웹 등)에서 "언어의 일반적 구조"를 먼저 학습하고,
  특정 태스크(분류, 번역 등)에 적은 데이터로 미세 조정(fine-tuning).

  왜 혁명적인가:
    과거: 각 태스크마다 처음부터 모델을 학습 → 데이터 많이 필요
    현재: 대규모 사전학습 + 소량 파인튜닝 → 적은 데이터로도 높은 성능!
    
    비유: 외국어를 배울 때
      처음부터 의학 논문을 읽는 것 vs 먼저 일상 회화를 배우고 의학 용어를 추가로 배우는 것
      → 후자가 훨씬 효율적!
```

### 7.2 BERT vs GPT — 왜 두 가지 접근인가

```
🔴 BERT (Bidirectional Encoder Representations from Transformers, 2018):
  인코더만 사용. 양방향 문맥.
  
  사전학습 방법: MLM (Masked Language Model)
    "The [MASK] sat on the mat" → [MASK] = "cat" 예측
    → 양쪽 문맥을 모두 보고 빈칸을 채우는 학습
  
  강점: 이해(understanding) 태스크 — 분류, NER, QA
  왜 양방향이 좋은가: "빈칸 채우기"는 앞뒤 맥락이 모두 필요.

🔴 GPT (Generative Pre-trained Transformer, 2018~):
  디코더만 사용. 단방향 (왼쪽→오른쪽).
  
  사전학습 방법: 다음 토큰 예측
    "The cat sat on" → 다음 토큰 = "the" 예측
    → 이전 토큰들만 보고 다음을 예측하는 학습
  
  강점: 생성(generation) 태스크 — 텍스트 생성, 대화, 코드 생성
  왜 단방향이 생성에 적합: 텍스트는 왼쪽에서 오른쪽으로 생성하니까.

  GPT → GPT-2 → GPT-3 → GPT-4:
    규모를 키우면 성능이 계속 향상! (스케일링 법칙)
    GPT-3: 175B 파라미터. Few-shot 학습 가능 (예시 몇 개만으로!)
    GPT-4: 멀티모달 (텍스트 + 이미지)

비교:
  ┌──────────┬──────────┬──────────┐
  │          │ BERT     │ GPT      │
  ├──────────┼──────────┼──────────┤
  │ 방향      │ 양방향    │ 단방향    │
  │ 구조      │ 인코더    │ 디코더    │
  │ 사전학습   │ 빈칸 채우기│ 다음 예측 │
  │ 강점      │ 이해      │ 생성     │
  │ 대표 용도  │ 분류, QA  │ 챗봇, 코드│
  └──────────┴──────────┴──────────┘
```

### 7.3 프롬프트 엔지니어링과 파인튜닝

```
🔴 파인튜닝 (Fine-tuning):
  사전학습 모델의 가중치를 특정 태스크의 데이터로 추가 학습.
  전체 가중치를 업데이트하거나, 일부만 (LoRA 등).

🔴 프롬프트 엔지니어링:
  모델의 가중치를 바꾸지 않고, 입력(프롬프트)을 잘 설계하여 원하는 출력을 유도.
  
  "다음 문장을 긍정/부정으로 분류하세요: '이 영화는 최고였다'" 
  → "긍정"
  
  Zero-shot: 예시 없이 지시만으로
  Few-shot: 예시 몇 개를 프롬프트에 포함
  Chain-of-Thought: "단계별로 생각하세요"라고 지시 → 추론 능력 향상!

🔴 RLHF (Reinforcement Learning from Human Feedback):
  인간 평가자가 모델 출력을 비교·평가 → 보상 모델 학습 → 강화학습으로 모델 조정.
  → ChatGPT가 "도움이 되고 안전한" 응답을 하는 핵심 기법.
```

## 8. 핵심 NLP 태스크와 평가

### 8.1 주요 태스크

```
🔵 텍스트 분류: 감성 분석, 스팸 탐지, 주제 분류
   개체명 인식 (NER): 텍스트에서 인명, 지명, 기관명 추출
   질의응답 (QA): 질문에 대한 답을 텍스트에서 찾기
   기계 번역: 한 언어 → 다른 언어
   요약: 긴 텍스트를 짧게 축약
   대화: 챗봇, 가상 비서
```

### 8.2 평가 지표

```
🔴 Perplexity (퍼플렉서티): PPL = 2^{H(P,Q)}
  "모델이 다음 토큰에 대해 평균적으로 몇 가지 선택지에서 고민하는가"
  낮을수록 좋다. PPL = 1이면 완벽한 예측.
  → Ch.08 크로스 엔트로피의 직접 응용!

🔴 BLEU (Bilingual Evaluation Understudy): 기계 번역 평가
  기계 번역과 참조 번역의 n-gram 겹침 정도.
  0~1, 높을수록 좋다.

🔴 ROUGE: 요약 평가
  요약과 참조 요약의 n-gram 겹침 (재현율 중심).
```

## 10. 정리

```
[원리 1] 분포 가설: 비슷한 문맥의 단어는 비슷한 의미. 임베딩의 근거.
[원리 2] 서브워드 토크나이징: 단어/문자의 절충. OOV 해결 + 적정 어휘 크기.
[원리 3] RNN의 순환: 이전 정보를 은닉 상태로 전달. 장기 의존성 → LSTM 게이트.
[원리 4] Attention: "모든 입력에 동등하게 집중하지 않는다." Q·K로 관련도 계산.
[원리 5] Transformer: Attention만으로 순차 모델을 대체. 병렬화 가능 = 규모 확장.
[원리 6] 사전학습 + 파인튜닝: 일반 지식을 먼저 학습 → 적은 데이터로 특화.
[원리 7] 규모의 법칙: 모델↑ + 데이터↑ + 컴퓨팅↑ → 성능↑ (예측 가능한 관계).

외워야 할 것:
  🔴 BPE의 원리 (빈도 기반 서브워드 병합)
  🔴 Self-Attention 수식: softmax(QK^T/√d_k) · V
  🔴 BERT = 인코더 + MLM, GPT = 디코더 + 다음 토큰 예측
  🔴 Transformer가 RNN을 대체한 이유 (병렬화 + 장거리 의존성)
  🔴 Perplexity = 2^{크로스 엔트로피}
```
