### 읽기 예시

```
∀x ∈ ℤ, ∃y ∈ ℤ : x + y = 0
→ "모든 정수 x에 대해, x + y = 0인 정수 y가 존재한다"
→ (모든 정수에는 덧셈 역원이 있다는 뜻)

p ∧ (q ∨ r) ≡ (p ∧ q) ∨ (p ∧ r)
→ "p 그리고 (q 또는 r)은, (p 그리고 q) 또는 (p 그리고 r)과 논리적으로 동치이다"
→ 이것이 분배법칙

|P(A)| = 2^|A|
→ "A의 멱집합의 크기는 2의 A의 크기 제곱이다"

a ≡ b (mod n)
→ "a와 b는 n으로 나눈 나머지가 같다" 또는 "a 합동 b 모드 n"
```

## 1. 출발점: 왜 이산수학이 CS의 언어인가

### 1.1 "이산"이란

```
이산(discrete) ↔ 연속(continuous)

  연속: 실수처럼 값 사이에 무한히 많은 중간값이 존재
  이산: 정수처럼 값 사이에 "간격"이 존재, 셀 수 있음

컴퓨터는 본질적으로 이산적이다:
  - 비트: 0 또는 1 (중간값 없음)
  - 메모리 주소: 정수
  - 알고리즘 단계: 셀 수 있는 연산의 나열
  - 데이터: 유한 개의 레코드
  - 그래프: 유한 개의 노드와 간선

→ 컴퓨터가 다루는 대상을 수학적으로 기술하려면 이산수학이 필요하다.
  미적분이 물리학의 언어라면, 이산수학은 CS의 언어이다.
```

## 2. 명제 논리 — 참과 거짓의 계산

### 2.1 명제란

```
🔴 [정의] 명제(proposition): 참(T) 또는 거짓(F)이 명확히 결정되는 문장

  명제인 것:     "2는 짝수이다" (참), "3 > 5" (거짓)
  명제가 아닌 것: "x > 5" (x를 모르면 판단 불가), "문을 닫아라" (명령)
```

### 2.2 논리 연결사 — 왜 이 다섯 가지인가

```
🔴 [정의] 기본 논리 연결사와 진리표:

  ¬p (NOT):        p가 참이면 거짓, 거짓이면 참
  p ∧ q (AND):     둘 다 참일 때만 참
  p ∨ q (OR):      하나라도 참이면 참
  p → q (조건, IF-THEN):  p가 참이고 q가 거짓일 때만 거짓
  p ↔ q (쌍조건, IFF):     둘의 진리값이 같을 때 참

진리표:
  p | q | ¬p | p∧q | p∨q | p→q | p↔q
  ──┼───┼────┼─────┼─────┼─────┼─────
  T | T |  F |  T  |  T  |  T  |  T
  T | F |  F |  F  |  T  |  F  |  F
  F | T |  T |  F  |  T  |  T  |  F
  F | F |  T |  F  |  F  |  T  |  T
```

**p → q에서 "p가 거짓이면 무조건 참"인 이유 — 가장 헷갈리는 부분:**

```
p → q = "p이면 q이다"

왜 p가 거짓일 때 전체가 참인가:

  약속: "비가 오면 우산을 가져간다" (p → q)
  
  비가 오고(p=T) 우산을 가져갔다(q=T): 약속 지킴 → T
  비가 오고(p=T) 우산 안 가져갔다(q=F): 약속 어김 → F
  비가 안 오고(p=F) 우산을 가져갔다(q=T): 약속 위반 아님 → T
  비가 안 오고(p=F) 우산 안 가져갔다(q=F): 약속 위반 아님 → T

  핵심: p → q는 "p가 참인데 q가 거짓인 경우만 거짓"이다.
  p가 거짓이면 약속이 적용되지 않으므로, 위반할 수 없다.
  → "공허하게 참(vacuously true)"이라 한다.

🔵 [CS 연결]
  프로그래밍: if (p) then q
  p가 false이면 q는 실행되지 않는다 → 조건 자체가 무의미 → 오류 아님
  
  알고리즘 정당성 증명: "입력이 정렬되어 있으면(p), 이진탐색이 정답을 찾는다(q)"
  입력이 정렬되지 않았으면? → 아무 말도 안 한 것. 약속 위반이 아님.
```

### 2.3 논리적 동치 — 외울 것과 유도할 것

```
🔴 [외워야 할 핵심 동치] — 나머지를 유도하는 기반이 되므로:

  드모르간 법칙 (De Morgan's Laws):
    ¬(p ∧ q) ≡ ¬p ∨ ¬q     "둘 다인 것의 부정 = 하나라도 아닌 것"
    ¬(p ∨ q) ≡ ¬p ∧ ¬q     "하나라도인 것의 부정 = 둘 다 아닌 것"

  왜 이것이 성립하는가:
    "비가 오고 바람이 분다"의 부정 = "비가 안 오거나 바람이 안 분다"
    하나라도 안 되면 "둘 다"는 깨진다 → AND의 부정은 OR
    
    "비가 오거나 바람이 분다"의 부정 = "비도 안 오고 바람도 안 분다"
    어느 것도 안 되어야 "하나라도"가 깨진다 → OR의 부정은 AND

  🔵 [CS 연결]
    코드에서: !(a && b) 는 (!a || !b)와 같다
    회로에서: NAND게이트 = NOT(AND), NOR게이트 = NOT(OR)

  조건문의 동치:
    p → q ≡ ¬p ∨ q        "p이면 q" = "p가 아니거나 q"
    
    왜: p → q가 거짓인 유일한 경우는 p=T, q=F.
    ¬p ∨ q가 거짓인 유일한 경우도 ¬p=F, q=F 즉 p=T, q=F.
    거짓인 경우가 동일하므로 동치.

  대우 (Contrapositive):
    p → q ≡ ¬q → ¬p       "p이면 q" = "q가 아니면 p도 아니다"

    왜: p → q ≡ ¬p ∨ q ≡ ¬q → ¬p  (위의 변환을 두 번 적용)
    
    "비가 오면 땅이 젖는다" ≡ "땅이 안 젖었으면 비가 안 온 것이다"
    
    🔵 대우를 이용한 증명은 수학과 CS에서 매우 자주 쓰인다.
    직접 증명이 어려울 때 대우를 증명하면 된다.

🟢 [유도 가능] — 진리표로 확인하면 되므로 외울 필요 없다:
  교환법칙: p ∧ q ≡ q ∧ p,  p ∨ q ≡ q ∨ p
  결합법칙: (p ∧ q) ∧ r ≡ p ∧ (q ∧ r)
  분배법칙: p ∧ (q ∨ r) ≡ (p ∧ q) ∨ (p ∧ r)
  이중 부정: ¬(¬p) ≡ p
  흡수법칙: p ∨ (p ∧ q) ≡ p
```

## 3. 술어 논리 — "모든"과 "존재"

### 3.1 왜 명제 논리만으로는 부족한가

```
명제 논리로는 "모든 짝수는 2로 나누어진다"를 표현할 수 없다.
"모든"이나 "어떤"을 다루려면 변수와 한정 기호(quantifier)가 필요하다.

🔴 [정의]
  술어 (predicate): 변수를 포함하는 문장. 변수에 값을 넣으면 명제가 됨.
    P(x) = "x는 짝수이다"  → P(4) = T, P(3) = F

  전칭 기호 (universal quantifier): ∀
    ∀x P(x) = "모든 x에 대해 P(x)가 참"

  존재 기호 (existential quantifier): ∃
    ∃x P(x) = "P(x)가 참인 x가 적어도 하나 존재"
```

**한정 기호의 부정 — 왜 이렇게 뒤집히는가:**

```
🟢 [유도 가능]

  ¬(∀x P(x)) ≡ ∃x ¬P(x)
  "모든 x가 P를 만족하는 것은 아니다" = "P를 만족하지 않는 x가 존재한다"

  ¬(∃x P(x)) ≡ ∀x ¬P(x)
  "P를 만족하는 x가 존재하지 않는다" = "모든 x가 P를 만족하지 않는다"

왜:
  "모든 학생이 시험에 합격했다"의 부정
  = "합격하지 못한 학생이 적어도 한 명 있다" (∀의 부정 = ∃¬)
  
  "시험에 합격한 학생이 있다"의 부정
  = "모든 학생이 시험에 합격하지 못했다" (∃의 부정 = ∀¬)

  이것은 드모르간 법칙의 확장이다:
    ∀ = 무한 AND,  ∃ = 무한 OR
    ¬(무한 AND) = 무한 OR(¬)
    ¬(무한 OR) = 무한 AND(¬)

🔵 [CS 연결]
  프로그램 검증:
    "이 프로그램은 모든 입력에 대해 올바르게 동작한다"의 반증
    = "올바르게 동작하지 않는 입력이 하나라도 있다" (반례 찾기)
  
  SQL: WHERE NOT EXISTS (...) ≡ WHERE FOR ALL NOT (...)
```

## 4. 증명 기법 — 왜 이런 방법들이 존재하는가

### 4.1 증명이 왜 중요한가

```
CS에서 증명이 필요한 순간:
  - "이 알고리즘은 항상 올바른 답을 준다" → 정당성 증명
  - "이 알고리즘은 O(n log n) 이하이다" → 복잡도 증명
  - "이 프로토콜은 안전하다" → 보안 증명
  - "이 자료구조의 삽입은 O(log n)이다" → 성능 보장
```

### 4.2 직접 증명 — 가장 단순한 방법

```
p → q를 증명하려면: p가 참이라고 가정하고, q가 참임을 보인다.

예시: "n이 짝수이면 n²도 짝수이다"
  가정: n은 짝수 → n = 2k (정수 k)
  그러면: n² = (2k)² = 4k² = 2(2k²)
  2k²은 정수이므로 n²은 짝수. □

이것이 가장 자연스러운 증명 방법이다.
"가정에서 출발하여 논리적 단계를 밟아 결론에 도달"
```

### 4.3 대우 증명 — 정면이 어려울 때 뒷길로

```
p → q 대신 ¬q → ¬p를 증명한다. (동치이므로 동일한 효력)

예시: "n²이 짝수이면 n도 짝수이다" (직접 증명이 어렵다)
  대우: "n이 홀수이면 n²도 홀수이다"
  가정: n = 2k+1
  n² = (2k+1)² = 4k²+4k+1 = 2(2k²+2k)+1 → 홀수. □

왜 대우를 쓰는가:
  "짝수이면"이라는 가정(n = 2k)에서 출발하는 것보다
  "홀수이면"이라는 가정(n = 2k+1)에서 출발하는 것이 더 다루기 쉬울 때.
```

### 4.4 귀류법 — 모순으로 몰아넣기

```
증명하려는 것의 부정을 가정하고, 모순을 이끌어낸다.

예시: "√2는 무리수이다"
  가정: √2가 유리수라고 하자 → √2 = p/q (기약분수, gcd(p,q) = 1)
  양변 제곱: 2 = p²/q² → p² = 2q² → p²은 짝수 → p는 짝수
  p = 2k로 놓으면: (2k)² = 2q² → 4k² = 2q² → q² = 2k² → q도 짝수
  
  p도 짝수, q도 짝수 → gcd(p,q) ≥ 2 → 기약분수라는 가정에 모순!
  따라서 √2는 유리수가 아니다 = 무리수이다. □

왜 귀류법이 작동하는가:
  논리적으로 모순에서는 어떤 결론이든 나올 수 있다 (ex falso quodlibet).
  모순이 발생했다는 것은 가정이 잘못되었다는 것.
  가정의 부정(즉 원래 주장)이 참이어야 한다.
```

### 4.5 수학적 귀납법 — CS에서 가장 많이 쓰는 증명

```
🔴 [원리] 수학적 귀납법 (Mathematical Induction):

  자연수에 대한 명제 P(n)을 증명하려면:
  
  (1) 기저 단계 (Base case): P(0) 또는 P(1)이 참임을 보인다
  (2) 귀납 단계 (Inductive step): P(k)가 참이면 P(k+1)도 참임을 보인다
  
  그러면 모든 n ≥ 0에 대해 P(n)이 참이다.

왜 이것이 작동하는가:
  도미노에 비유하면:
  (1) 첫 번째 도미노를 넘어뜨린다 (기저)
  (2) 하나가 넘어지면 다음도 넘어진다 (귀납)
  → 모든 도미노가 넘어진다

  P(0) 참 → P(1) 참 → P(2) 참 → P(3) 참 → ...
  체인이 끊기지 않으므로 모든 자연수에 대해 성립.
```

**예시: 1 + 2 + ... + n = n(n+1)/2**

```
기저: n = 1일 때, 1 = 1·2/2 = 1. ✓

귀납 가정: P(k)가 참이라고 가정: 1 + 2 + ... + k = k(k+1)/2

귀납 단계: P(k+1)을 보인다:
  1 + 2 + ... + k + (k+1)
  = k(k+1)/2 + (k+1)         ← 귀납 가정 사용
  = (k+1)(k/2 + 1)
  = (k+1)(k+2)/2             ← P(k+1)의 형태. ✓

🔵 [CS 연결]
  재귀 알고리즘의 정당성 증명:
    기저: 입력 크기 0(또는 1)에서 올바르게 동작
    귀납: 크기 k에서 올바르면 크기 k+1에서도 올바름
    → 재귀 구조와 귀납법의 구조가 정확히 일치한다!
  
  자료구조의 성질 증명:
    "높이 h인 이진 트리의 노드 수 ≤ 2^(h+1) - 1"
    → h에 대한 귀납법으로 증명
```

**강한 귀납법 (Strong Induction):**

```
귀납 단계에서 P(k)만이 아니라 P(0), P(1), ..., P(k) 모두를 가정한다.

왜 이것도 유효한가:
  "이전의 모든 도미노가 넘어졌으면 다음도 넘어진다"
  보통 귀납법과 동치이지만, 증명이 더 쉬운 경우가 많다.
  
  예: "모든 2 이상의 자연수는 소수의 곱으로 표현된다"
  → n이 소수이면 자명. 합성수이면 n = ab이고 a,b < n.
  → 강한 귀납 가정에 의해 a, b 모두 소수의 곱.
  → n = ab도 소수의 곱. □
```

## 5. 집합론 기초 — 수학의 건축 자재

### 5.1 집합이란 — CS에서 왜 중요한가

```
🔴 [정의] 집합(set): 구별되는 대상(원소)의 모임. 순서 없음, 중복 없음.

  {1, 2, 3} = {3, 1, 2} = {1, 1, 2, 3}  (순서·중복 무관)

왜 CS에서 집합이 중요한가:
  - DB 테이블 = 튜플의 집합
  - 타입 = 값의 집합 (int = 정수의 집합)
  - 그래프의 정점 집합, 간선 집합
  - 프로그래밍 언어의 Set, HashSet 자료구조
```

### 5.2 집합 연산 — 왜 이런 연산들이 필요한가

```
🔴 [정의] + 논리 연결사와의 대응:

  ∪ (합집합): A 또는 B → 논리의 OR (∨)
  ∩ (교집합): A 그리고 B → 논리의 AND (∧)
  Aᶜ (여집합): A가 아닌 것 → 논리의 NOT (¬)
  A \ B (차집합): A이고 B가 아닌 것 → A ∧ ¬B

  집합 연산과 논리 연산이 완벽히 대응한다!
  드모르간 법칙도 그대로 성립:
  
  (A ∪ B)ᶜ = Aᶜ ∩ Bᶜ     ← 논리의 ¬(p ∨ q) ≡ ¬p ∧ ¬q
  (A ∩ B)ᶜ = Aᶜ ∪ Bᶜ     ← 논리의 ¬(p ∧ q) ≡ ¬p ∨ ¬q

  🟢 왜 같은가: 집합의 원소 x에 대해 "x ∈ A"를 명제로 보면,
  집합 연산이 논리 연산으로 번역된다. 같은 구조이므로 같은 법칙이 성립.
```

### 5.3 멱집합과 카르테시안 곱

```
🔴 [정의]
  멱집합 P(A): A의 모든 부분집합의 집합
  |P(A)| = 2^|A|

  왜 2^|A|인가:
    각 원소에 대해 "포함한다(1)/안 한다(0)"의 선택이 독립적.
    n개 원소, 각각 2가지 선택 → 2ⁿ가지
    
    이것은 n비트 이진수와 일대일 대응이다:
    A = {a, b, c}이면:
    000 → ∅, 001 → {c}, 010 → {b}, 011 → {b,c}, ...
    
    🔵 부분집합 열거 문제 = 비트마스크 순회 (알고리즘에서 자주 사용)

  카르테시안 곱 A × B: 순서쌍 (a, b)의 집합 (a ∈ A, b ∈ B)
  |A × B| = |A| · |B|

  왜 중요한가:
    DB의 테이블 = 속성 도메인들의 카르테시안 곱의 부분집합
    ℝ² = ℝ × ℝ (2차원 좌표 평면)
```

## 6. 관계 — 원소 사이의 "연결"

### 6.1 관계란

```
🔴 [정의] A에서 B로의 이항 관계(binary relation) R:
  R ⊆ A × B

  (a, b) ∈ R이면 "a와 b는 관계 R에 있다"고 하고, aRb로 쓴다.

예시:
  "작거나 같다" ≤: {(1,1), (1,2), (1,3), (2,2), (2,3), (3,3), ...}
  "...의 친구이다": 사람 집합에서의 관계
```

### 6.2 관계의 성질 — 왜 이 네 가지인가

```
🔴 [정의] A 위의 관계 R에 대해:

  반사적 (reflexive): ∀a ∈ A, aRa
    "자기 자신과 관계가 있다"
    예: ≤ (3 ≤ 3), = (3 = 3)

  대칭적 (symmetric): aRb → bRa
    "관계가 양방향이다"
    예: "...의 친구" (내가 네 친구면 너도 내 친구)

  반대칭적 (antisymmetric): aRb ∧ bRa → a = b
    "양방향이면 같은 원소"
    예: ≤ (a ≤ b이고 b ≤ a이면 a = b)

  추이적 (transitive): aRb ∧ bRc → aRc
    "관계가 전달된다"
    예: < (a < b이고 b < c이면 a < c)

왜 이 네 가지가 중요한가:
  이 성질들의 조합으로 수학에서 가장 중요한 관계 유형이 정의된다.
```

### 6.3 동치 관계와 부분 순서 — 두 가지 핵심 유형

```
🔴 [정의]
  동치 관계 (equivalence relation): 반사 + 대칭 + 추이
    "같은 종류"로 묶는 관계. 집합을 겹치지 않는 클래스로 분할한다.
    
    예: "같은 나머지" (mod n)
    7 ≡ 2 (mod 5) → 7과 2는 "mod 5로 같은 클래스"
    
    🔵 [CS 연결]
    해시 함수: 같은 해시값을 가지는 키들 → 동치 클래스
    타입 시스템: 같은 타입으로 취급되는 값들 → 동치 클래스
    그래프의 연결 요소: 서로 도달 가능한 노드들 → 동치 클래스

  부분 순서 (partial order): 반사 + 반대칭 + 추이
    "크기 비교"가 가능하지만, 모든 쌍이 비교 가능하지는 않은 관계.
    
    예: 집합의 포함 관계 ⊆
    {1} ⊆ {1,2}, {2} ⊆ {1,2}, 하지만 {1}과 {2}는 비교 불가
    
    전순서 (total order): 부분 순서 + 모든 쌍이 비교 가능
    예: ≤ (실수 위의 순서)
    
    🔵 [CS 연결]
    위상 정렬: 부분 순서를 선형(전순서)으로 펼치는 것
    작업 스케줄링: 선행 조건 = 부분 순서, 실행 순서 = 위상 정렬
    정렬 알고리즘: 전순서가 있어야 정렬 가능
```

## 7. 함수 — 관계의 특별한 경우

### 7.1 함수의 종류 — 왜 이 분류가 중요한가

```
🔴 [정의] 함수 f: A → B
  A의 각 원소에 B의 원소를 정확히 하나 대응

분류:
  단사 (injective, one-to-one):
    f(a₁) = f(a₂) → a₁ = a₂
    "다른 입력은 다른 출력" — 정보 손실 없음
    
  전사 (surjective, onto):
    ∀b ∈ B, ∃a ∈ A : f(a) = b
    "B의 모든 원소가 커버됨" — 빠짐 없음
    
  전단사 (bijective): 단사 + 전사
    일대일 대응. 역함수가 존재.

왜 이 분류가 중요한가:
  단사: 원래 입력을 복원 가능 (암호화, 해시의 이상적 성질)
  전사: 모든 출력이 달성 가능
  전단사: 두 집합의 크기가 같다는 증거
    |A| = |B| ⟺ A에서 B로의 전단사 함수가 존재

🔵 [CS 연결]
  해시 함수: 이상적으로 단사이고 싶지만, 입력 공간 > 출력 공간이면 불가능
  → 충돌(collision)이 불가피한 이유: 비둘기집 원리 (§8)
  
  인코딩/디코딩: 무손실 압축 = 전단사 (되돌릴 수 있어야)
  정보 이론의 소스 코딩: 전단사가 불가능하면 손실 압축
```

## 8. 셈 원리 — 경우의 수 세기

### 8.1 곱의 법칙과 합의 법칙

```
🔴 [원리]
  곱의 법칙: 독립적인 두 선택을 연달아 하면, 경우의 수는 곱
    "셔츠 5벌, 바지 3벌 → 조합 = 5 × 3 = 15가지"
    
  합의 법칙: 배타적인 두 경우 중 하나를 선택하면, 경우의 수는 합
    "버스 3노선 또는 지하철 2노선 → 선택 = 3 + 2 = 5가지"

왜 곱/합인가:
  곱: 각 선택이 독립적이면, 첫 선택의 각 경우에 대해 두 번째 선택의 모든 경우가 가능
  합: 경우가 겹치지 않으면, 전체 = 각 경우를 모두 합산

🔵 [CS 연결]
  비밀번호의 경우의 수:
    8자리, 각 자리 62가지(대소영문자+숫자) → 62⁸ ≈ 2×10¹⁴ (곱의 법칙)
  
  알고리즘 복잡도:
    중첩 루프: 바깥 n번 × 안쪽 m번 = O(nm) (곱의 법칙)
    조건 분기: if일 때 O(f) 또는 else일 때 O(g) = O(max(f,g)) (합의 법칙)
```

### 8.2 순열과 조합 — 왜 이 구분이 필요한가

```
🔴 [정의]
  순열 (permutation): 순서가 중요한 배열
    P(n, k) = n! / (n-k)!
    "n개에서 k개를 뽑아 줄 세우기"

  조합 (combination): 순서가 중요하지 않은 선택
    C(n, k) = n! / (k!(n-k)!)
    "n개에서 k개를 뽑기" (순서 무관)

왜 C(n,k) = P(n,k) / k! 인가:
  순열: 뽑고 줄 세운다 → P(n,k)가지
  조합: 뽑기만 한다 → 같은 k개를 줄 세우는 k!가지가 중복
  
  중복을 제거: C(n,k) = P(n,k) / k! = n! / (k!(n-k)!)

예시:
  5명 중 3명을 뽑아 줄 세우기: P(5,3) = 60
  5명 중 3명을 뽑기:          C(5,3) = 10
  60 / 10 = 6 = 3! (같은 3명의 줄 세우기 경우의 수)

🔵 [CS 연결]
  부분집합의 수: C(n,k) = k개짜리 부분집합의 수
  이항분포: C(n,k) · pᵏ(1-p)ⁿ⁻ᵏ → C(n,k)가 여기서 나온다 (Ch.03)
  경쟁 프로그래밍: 조합론 문제의 기본 도구
```

### 8.3 비둘기집 원리 — 단순하지만 강력한 존재 증명

```
🔴 [원리] 비둘기집 원리 (Pigeonhole Principle):
  n+1개의 물건을 n개의 상자에 넣으면, 적어도 하나의 상자에 2개 이상 들어간다.

왜 자명한가:
  각 상자에 최대 1개씩 넣으면 n개까지만 배치 가능.
  n+1개째는 반드시 이미 차 있는 상자에 가야 한다.

일반화: mn+1개를 n개 상자에 넣으면, 적어도 하나에 m+1개 이상.

🔵 [CS 연결]
  해시 충돌은 피할 수 없다:
    입력 공간이 해시 테이블 크기보다 크면 → 비둘기집 원리에 의해 충돌 발생
    
  생일 문제:
    23명만 모여도 같은 생일이 있을 확률 > 50%
    365개 "상자"(생일)에 23명 → 비둘기집은 아니지만 확률적으로 높다
    
  무손실 압축의 한계:
    n비트 문자열 2ⁿ개를 n비트 미만으로 모두 표현할 수 없다
    → 비둘기집 원리에 의해, 어떤 압축이든 일부 입력은 오히려 길어진다
```

## 9. 그래프 이론 — CS의 가장 중요한 수학적 모델

### 9.1 그래프란 — 왜 이것이 어디에나 등장하는가

```
🔴 [정의] 그래프 G = (V, E)
  V = 정점(vertex) 집합 (= 노드, node)
  E = 간선(edge) 집합 ⊆ V × V (= 링크, link)

  무방향 그래프: 간선에 방향 없음. {u, v}
  방향 그래프 (directed): 간선에 방향 있음. (u, v) ≠ (v, u)

왜 어디에나 등장하는가:
  "대상들 사이의 관계"는 거의 모든 것을 표현할 수 있기 때문.
  
  ┌──────────────────┬────────────────┬─────────────┐
  │ 현실              │ 정점            │ 간선         │
  ├──────────────────┼────────────────┼─────────────┤
  │ 소셜 네트워크     │ 사용자          │ 친구 관계     │
  │ 웹               │ 웹 페이지       │ 하이퍼링크    │
  │ 도로망            │ 교차로          │ 도로         │
  │ 컴퓨터 네트워크   │ 라우터/호스트   │ 연결         │
  │ 의존성 관리       │ 패키지/모듈     │ 의존 관계     │
  │ 컴파일러          │ 코드 블록       │ 제어 흐름     │
  │ DB의 ER 다이어그램│ 엔티티          │ 관계         │
  └──────────────────┴────────────────┴─────────────┘
```

### 9.2 그래프의 기본 용어

```
차수 (degree): 정점에 연결된 간선 수
  방향 그래프: 진입 차수(in-degree), 진출 차수(out-degree)

경로 (path): 간선으로 연결된 정점의 수열
  단순 경로: 정점이 반복되지 않는 경로
  
사이클 (cycle): 시작점 = 끝점인 경로

연결 (connected): 모든 정점 쌍 사이에 경로가 존재
  연결 요소 (connected component): 최대 연결 부분 그래프

🟢 [유도 가능] 악수 정리 (Handshaking Lemma):
  Σ deg(v) = 2|E|  (모든 정점 차수의 합 = 간선 수의 2배)
  
  왜: 각 간선은 두 정점의 차수에 1씩 기여한다. 따라서 총 기여 = 2|E|.
  
  결과: 홀수 차수 정점의 수는 항상 짝수이다.
```

### 9.3 특별한 그래프 유형

```
트리 (tree): 사이클이 없는 연결 그래프
  🟢 n개 정점의 트리는 정확히 n-1개 간선을 가진다.
  
  왜: 트리에서 간선 하나를 제거하면 비연결이 된다 (최소 연결).
  n개 정점을 연결하는 데 필요한 최소 간선 = n-1.
  
  🔵 [CS 연결] 자료구조의 트리, 스패닝 트리, 결정 트리

이분 그래프 (bipartite): 정점을 두 그룹으로 나눌 수 있고,
  같은 그룹 내 간선이 없는 그래프.
  
  🟢 이분 그래프 ⟺ 홀수 길이의 사이클이 없다
  
  🔵 매칭 문제: 학생↔프로젝트 배정, 구직자↔일자리

완전 그래프 Kₙ: 모든 정점 쌍이 연결. 간선 수 = C(n,2) = n(n-1)/2

평면 그래프: 간선이 교차하지 않게 평면에 그릴 수 있는 그래프
  🔴 오일러 공식: V - E + F = 2  (V: 정점, E: 간선, F: 면)
  🟢 결과: 평면 그래프에서 E ≤ 3V - 6 (V ≥ 3일 때)
```

### 9.4 오일러와 해밀턴 — 왜 난이도가 이렇게 다른가

```
오일러 경로/회로: 모든 간선을 정확히 한 번 통과
  오일러 회로 존재 ⟺ 모든 정점의 차수가 짝수 (+ 연결)
  오일러 경로 존재 ⟺ 홀수 차수 정점이 0개 또는 2개

  왜: 한 정점을 지날 때마다 들어오는 간선과 나가는 간선이 쌍을 이뤄야.
  시작/끝점이 아닌 정점은 반드시 짝수 차수여야 한다.
  
  → 다항 시간에 판정 가능 (차수만 세면 됨)

해밀턴 경로/회로: 모든 정점을 정확히 한 번 방문
  판정 조건? → 알려진 간단한 필요충분조건이 없다!
  → NP-완전 문제 (Ch.10)
  
  왜 이렇게 다른가:
  간선 → 각 간선에 대한 "지역적" 조건 (차수) 으로 판정 가능
  정점 → "전역적" 구조를 봐야 함 → 모든 경우를 탐색해야 할 수 있음
  
  🔵 TSP(외판원 문제)가 NP-hard인 이유: 해밀턴 회로의 최적화 버전
```

### 9.5 그래프 탐색 — BFS와 DFS

```
🔵 [CS 연결] 그래프의 가장 기본적인 알고리즘 (Ch.10에서 상세)

BFS (Breadth-First Search, 너비 우선):
  시작점에서 가까운 것부터 탐색. 큐(queue) 사용.
  → 최단 경로 (비가중 그래프)

DFS (Depth-First Search, 깊이 우선):
  한 방향으로 끝까지 간 후 되돌아옴. 스택(stack)/재귀 사용.
  → 사이클 감지, 위상 정렬, 연결 요소

탐색 순서 비교:

  그래프:  1 — 2 — 5
           |   |
           3 — 4

  BFS (시작: 1): 1 → 2, 3 → 4, 5    (레벨별)
  DFS (시작: 1): 1 → 2 → 4 → 3 → 5  (깊이 우선)
```

## 10. 오토마타와 형식 언어 — 계산의 수학적 모델

### 10.1 왜 오토마타를 배우는가

```
오토마타(automata) = 가장 단순한 형태의 "기계"의 수학적 모델

왜 중요한가:
  "이 문제를 컴퓨터로 풀 수 있는가?"라는 근본 질문에 답한다.
  컴파일러의 렉서(lexer)는 유한 오토마타로 구현된다.
  정규 표현식의 이론적 기반이 유한 오토마타이다.
```

### 10.2 촘스키 위계 — 언어와 기계의 대응

```
🔴 [외워야 할 체계]

  ┌─────────────────┬──────────────────┬───────────────────┐
  │ 문법 유형         │ 인식하는 기계       │ 예시               │
  ├─────────────────┼──────────────────┼───────────────────┤
  │ Type 3: 정규     │ 유한 오토마타 (FA)  │ 정규 표현식         │
  │ Type 2: 문맥 자유 │ 푸시다운 오토마타   │ 프로그래밍 언어 문법 │
  │ Type 1: 문맥 의존 │ 선형유한 오토마타   │ 자연어의 일부       │
  │ Type 0: 재귀 열거 │ 튜링 머신          │ 모든 알고리즘       │
  └─────────────────┴──────────────────┴───────────────────┘

  Type 3 ⊂ Type 2 ⊂ Type 1 ⊂ Type 0

왜 이 계층이 중요한가:
  각 수준은 "더 강력한 기계가 필요한 언어"를 정의한다.
  정규 언어는 가장 단순하고, 유한 오토마타로 충분하다.
  문맥 자유 언어는 스택이 추가로 필요하다.
  모든 것을 다 할 수 있는 것은 튜링 머신뿐이다.
```

### 10.3 유한 오토마타 — 가장 단순한 계산 모델

```
🔴 [정의] DFA (Deterministic Finite Automaton):
  M = (Q, Σ, δ, q₀, F)

  Q:  상태(state)의 유한 집합
  Σ:  입력 알파벳
  δ:  전이 함수 δ: Q × Σ → Q  ("이 상태에서 이 입력을 받으면 어디로 가는가")
  q₀: 시작 상태
  F:  수락 상태(accept state)의 집합

  동작: 입력 문자열을 한 글자씩 읽으며 상태를 전이.
       마지막 상태가 F에 속하면 수락(accept), 아니면 거부(reject).

예시: "01을 포함하는 이진 문자열"을 인식하는 DFA

  상태: S₀(시작), S₁(0을 봄), S₂(01을 봄, 수락)

         0          1           0,1
  → (S₀) ──→ (S₁) ──→ ((S₂)) ──→ ((S₂))
      ↑   1    ↑  0      
      └───┘    └──┘

  S₀에서 0을 읽으면 S₁로 (0을 기억)
  S₁에서 1을 읽으면 S₂로 (01 패턴 발견!)
  S₂는 수락 상태, 이후 무엇이 와도 수락 유지
```

### 10.4 정규 표현식과의 관계

```
🔴 [핵심 동치] 정규 언어에 대해 다음 세 가지는 동치이다:

  (1) DFA로 인식 가능
  (2) NFA로 인식 가능
  (3) 정규 표현식으로 표현 가능

왜 DFA = NFA인가:
  NFA(비결정적)는 여러 상태에 동시에 있을 수 있다.
  이 "여러 상태의 집합"을 DFA의 하나의 상태로 보면 DFA로 변환 가능.
  → 부분집합 구성법 (subset construction)
  
  대가: 상태 수가 지수적으로 증가할 수 있다 (2^|Q|)

🔵 [CS 연결]
  grep, sed, 프로그래밍 언어의 정규식 → 내부적으로 NFA/DFA로 변환
  컴파일러의 렉서(tokenizer) → DFA로 구현
  네트워크 패킷 필터링 → 정규식 매칭
```

## 11. 재귀와 점화식 — 반복 구조의 수학

### 11.1 재귀적 정의 — 왜 이것이 자연스러운가

```
🔴 [원리] 재귀적 정의:
  (1) 기저 경우 (base case): 가장 작은 경우의 값을 직접 정의
  (2) 재귀 경우 (recursive case): 더 작은 경우로 환원하여 정의

예시: 팩토리얼
  0! = 1           (기저)
  n! = n · (n-1)!  (재귀)

왜 자연스러운가:
  많은 CS 문제는 "큰 문제를 작은 문제로 쪼개는" 구조를 가진다.
  재귀적 정의는 이 구조를 직접 반영한다.
  → 분할 정복, 동적 프로그래밍의 기반 (Ch.10)
```

### 11.2 점화식과 풀이 — 왜 닫힌 형태가 중요한가

```
점화식(recurrence relation): 수열의 다음 항을 이전 항으로 정의
  T(n) = 2T(n/2) + n  (머지 정렬의 복잡도)
  F(n) = F(n-1) + F(n-2)  (피보나치)

왜 닫힌 형태(closed form)를 구하는가:
  T(n) = 2T(n/2) + n만으로는 T(1000)을 빠르게 계산할 수 없다.
  T(n) = O(n log n)이라는 닫힌 형태를 알면 즉시 크기를 파악 가능.

🔴 [외워야 할 도구] 마스터 정리:
  T(n) = aT(n/b) + f(n) 형태의 점화식 풀이 (Ch.10에서 상세)
  
  Case 1: f(n) = O(n^(log_b(a)-ε)) → T(n) = Θ(n^(log_b(a)))
  Case 2: f(n) = Θ(n^(log_b(a)))  → T(n) = Θ(n^(log_b(a)) · log n)
  Case 3: f(n) = Ω(n^(log_b(a)+ε)) → T(n) = Θ(f(n))

피보나치의 닫힌 형태:
  🟢 F(n) = (φⁿ - ψⁿ) / √5
  여기서 φ = (1+√5)/2 ≈ 1.618 (황금비), ψ = (1-√5)/2 ≈ -0.618
  
  유도: 특성방정식 x² = x + 1의 근이 φ와 ψ.
  → 정수 수열이 무리수로 표현된다는 놀라운 결과!
```

## 13. 정리 — 이산수학을 관통하는 원리

```
[원리 1] 논리 = 참/거짓의 대수
  → 드모르간, 대우, 조건문의 의미를 정확히 이해하면 
    증명과 프로그래밍의 기반이 된다

[원리 2] 증명 = 논리적 사슬
  → 특히 귀납법 = 재귀와 동일 구조 (기저 + 재귀/귀납 단계)

[원리 3] 집합·관계·함수 = 수학적 구조의 기본 벽돌
  → DB, 타입 시스템, 그래프 모두 이 위에 세워짐

[원리 4] 셈 원리 = 곱(독립 선택)과 합(배타 선택)
  → 복잡도 분석, 확률 계산, 보안 분석의 기초

[원리 5] 그래프 = "관계"의 시각적·수학적 모델
  → CS의 가장 범용적인 모델링 도구

[원리 6] 오토마타 = "계산 능력의 계층"
  → 정규 ⊂ 문맥 자유 ⊂ 튜링 결정 가능 ⊂ 모든 언어

외워야 할 것:
  🔴 논리 연결사의 진리표 (특히 →의 정의)
  🔴 드모르간 법칙, 대우
  🔴 귀납법의 구조 (기저 + 귀납 단계)
  🔴 C(n,k) = n!/(k!(n-k)!) 와 그 의미
  🔴 촘스키 위계 (4단계)
  🔴 오일러 경로/회로 존재 조건 (차수 조건)

유도할 수 있는 것:
  🟢 한정 기호의 부정 (드모르간의 확장)
  🟢 조건문의 동치 (p→q ≡ ¬p∨q)
  🟢 C(n,k) 공식 (순열에서 중복 제거)
  🟢 악수 정리 (간선의 이중 기여)
  🟢 트리의 간선 수 = n-1
```
