## 1. 출발점: 알고리즘이란 무엇이고, 왜 분석하는가

### 1.1 알고리즘이란

```
🔴 [정의] 알고리즘: 문제를 풀기 위한 유한한 단계의 명확한 절차

  조건:
  (1) 입력: 0개 이상의 입력
  (2) 출력: 1개 이상의 출력
  (3) 명확성: 각 단계가 모호하지 않음
  (4) 유한성: 유한 단계 후 반드시 종료
  (5) 유효성: 각 단계가 실행 가능

레시피와의 차이:
  레시피: "소금을 적당히" → 모호 (명확성 위반)
  알고리즘: "소금 5g을 넣는다" → 명확
```

### 1.2 왜 복잡도를 분석하는가

```
같은 문제를 푸는 두 알고리즘:
  알고리즘 A: O(n²)
  알고리즘 B: O(n log n)

  n = 1,000:     A = 1,000,000    B ≈ 10,000      (100배 차이)
  n = 1,000,000: A = 10¹²         B ≈ 20,000,000   (50,000배 차이!)

  n이 커질수록 차이가 극적으로 벌어진다.
  → "큰 입력에서 어떻게 행동하는가"가 알고리즘의 본질적 효율을 결정한다.
  → 이것을 측정하는 도구가 점근적 복잡도 분석이다.
```

## 2. 복잡도 분석 — 알고리즘의 "체급"

### 2.1 Big-O — 왜 이 정의인가

```
🔴 [정의] f(n) = O(g(n)):
  충분히 큰 n에 대해 f(n) ≤ c · g(n)인 상수 c > 0, n₀가 존재한다.

왜 이렇게 정의하는가:
  "세부사항을 무시하고 성장 속도의 본질만 본다"

  3n² + 5n + 100 = O(n²)
  
  왜 5n과 100을 무시하는가:
    n이 충분히 크면 n² 항이 압도적으로 지배한다.
    n = 1000이면: 3,000,000 + 5,000 + 100 ≈ 3,000,000
    5n과 100은 전체의 0.17%에 불과하다.
  
  왜 상수 3도 무시하는가:
    컴퓨터마다 실행 속도가 다르다.
    3배 빠른 컴퓨터를 쓰면 상수가 바뀌지만, n²이라는 본질은 안 바뀐다.
    우리가 알고 싶은 것은 "n이 2배가 되면 시간이 몇 배가 되는가"이다.
    O(n²)이면 → 4배. O(n log n)이면 → 약 2배. 이것이 본질.
```

### 2.2 복잡도 계층 — 외워야 하는 "속도 순서"

```
🔴 [외워야 할 계층]

  O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)

  n = 1,000,000 (백만)일 때 대략적 연산 수:
  
  O(1):       1            ← 해시 테이블 접근
  O(log n):   20           ← 이진 탐색
  O(n):       1,000,000    ← 선형 스캔
  O(n log n): 20,000,000   ← 머지 정렬
  O(n²):      10¹²         ← 이중 루프 → 1초에 10⁹ 연산이면 ~17분
  O(2ⁿ):      10³⁰⁰⁰⁰⁰    ← 우주의 원자 수(10⁸⁰)보다 많음. 불가능.

  O(n log n)과 O(n²) 사이에 실용성의 벽이 있다.
  n = 10⁶에서:
    O(n log n) → 1초 이내
    O(n²) → 수 분
    O(2ⁿ) → 우주가 끝나도 못 끝남
```

### 2.3 Amortized 분석 — 가끔 비싼 것을 어떻게 평가하는가

```
🔴 [원리] 분할 상환 분석:
  "간헐적으로 비싼 연산이 있지만, 전체 n번의 평균으로 보면 싸다"

  동적 배열의 push: 보통 O(1), 가끔 O(n) (더블링 복사)
  
  n번 push의 총 비용:
    일반 push: n번 × O(1) = O(n)
    복사 비용: 1 + 2 + 4 + ... + n = 2n - 1 = O(n)
    총합: O(n) + O(n) = O(n)
    push 한 번당: O(n)/n = O(1) amortized

  핵심: "가끔 비싸지만, 비싼 연산을 할 때까지 싼 연산이 충분히 많다."
  비싼 연산의 비용을 싼 연산들에 분산하여 부담한다.
```

## 3. 분할 정복 — "큰 것을 쪼개라"

### 3.1 원리 — 왜 이것이 강력한가

```
🔴 [원리] 분할 정복 (Divide and Conquer):

  (1) Divide: 문제를 더 작은 부분 문제들로 분할
  (2) Conquer: 부분 문제를 재귀적으로 풀기
  (3) Combine: 부분 해를 합쳐서 원래 문제의 해 구성

왜 강력한가:
  문제를 매번 절반으로 줄이면 → log n 단계만에 기저에 도달
  각 단계에서 O(n) 작업 → 총 O(n log n)
  
  n을 절반으로 줄이는 힘:
    n = 1,000,000 → 500,000 → 250,000 → ... → 1  (20단계!)
    직접 풀면 100만 단계가, 분할 정복이면 20 × 100만 = 2000만 단계.
```

### 3.2 머지 정렬 — 분할 정복의 교과서적 예시

```
🔴 [알고리즘]
  (1) 배열을 절반으로 나눈다
  (2) 각 절반을 재귀적으로 정렬한다
  (3) 두 정렬된 절반을 합친다 (merge)

  [38, 27, 43, 3, 9, 82, 10]
         ↓ divide
  [38, 27, 43, 3]  [9, 82, 10]
     ↓                ↓
  [38,27] [43,3]   [9,82] [10]
    ↓       ↓        ↓      ↓
  [27,38] [3,43]  [9,82]  [10]
     ↓ merge          ↓ merge
  [3,27,38,43]    [9,10,82]
         ↓ merge
  [3, 9, 10, 27, 38, 43, 82]

  merge 단계가 핵심:
    두 정렬된 배열을 하나로 합치는 것은 O(n):
    각 배열의 앞에서부터 비교하며 작은 것을 순서대로 취한다.

왜 O(n log n)인가:
  T(n) = 2T(n/2) + O(n)
  
  분할: 2개의 크기 n/2 문제 → 2T(n/2)
  합병: 두 절반을 합치는 비용 → O(n)
  
  각 레벨의 총 작업량 = O(n) (항상 같다!)
  레벨 수 = log₂ n
  총 = O(n) × O(log n) = O(n log n)

  시각화:
  레벨 0: [────────── n ──────────]          작업 = n
  레벨 1: [──── n/2 ────][──── n/2 ────]    작업 = n
  레벨 2: [─ n/4 ─][─ n/4 ─][─ n/4 ─][─ n/4 ─]  작업 = n
  ...
  레벨 k: 각 크기 1, n개                    작업 = n
  
  → 모든 레벨에서 총 작업량 = n. 레벨 수 = log n. 총 = n log n.
```

### 3.3 마스터 정리 — 분할 정복 점화식의 만능 해법

```
🔴 [정리] T(n) = aT(n/b) + f(n) 형태의 점화식:

  a: 부분 문제의 수
  b: 부분 문제의 크기 축소 비율
  f(n): 분할+합병 비용

  c_crit = log_b(a)  (임계 지수)

  Case 1: f(n) = O(n^{c_crit - ε})    → T(n) = Θ(n^{c_crit})
    "재귀 비용이 지배" — 부분 문제 풀기가 합치기보다 비쌈

  Case 2: f(n) = Θ(n^{c_crit})        → T(n) = Θ(n^{c_crit} · log n)
    "비용이 균등" — 매 레벨에서 같은 비용

  Case 3: f(n) = Ω(n^{c_crit + ε})    → T(n) = Θ(f(n))
    "합치기 비용이 지배" — 합치는 것이 재귀보다 비쌈

예시:
  머지 정렬: T(n) = 2T(n/2) + n
    a=2, b=2, c_crit = log₂2 = 1, f(n) = n = Θ(n¹)
    → Case 2 → T(n) = Θ(n log n) ✓

  이진 탐색: T(n) = T(n/2) + O(1)
    a=1, b=2, c_crit = log₂1 = 0, f(n) = O(1) = Θ(n⁰)
    → Case 2 → T(n) = Θ(log n) ✓

왜 이 정리가 작동하는가:
  재귀 트리의 각 레벨에서 작업량을 합산한다.
  레벨이 내려갈수록 부분 문제 수는 a배 늘지만 크기는 1/b로 줄어든다.
  f(n)의 성장률에 따라 어느 쪽이 지배하는지가 결정된다.
```

## 4. 정렬 — 왜 이렇게 많은 알고리즘이 있는가

### 4.1 비교 기반 정렬의 하한 — 왜 O(n log n)보다 빠를 수 없는가

```
🔴 [정리] 비교 기반 정렬의 하한: Ω(n log n)

왜:
  n개 원소의 가능한 순열 = n!가지
  각 비교는 "예/아니오" → 2갈래로 나뉨
  k번의 비교로 구별할 수 있는 경우의 수 = 최대 2ᵏ
  
  모든 순열을 구별해야 하므로: 2ᵏ ≥ n!
  k ≥ log₂(n!) ≈ n log₂ n - n log₂ e ≈ n log₂ n
  
  → 최소 n log n번의 비교가 필요하다!
  → 머지 정렬, 힙 정렬은 이 하한에 도달한다 = 최적

  이것은 정보이론(Ch.08)의 응용이다:
    n!가지 가능성 → log₂(n!) 비트의 정보가 필요
    비교 하나 = 1비트의 정보 획득
    → 최소 log₂(n!) ≈ n log n번의 비교
```

### 4.2 주요 정렬 알고리즘 — 각각의 존재 이유

```
🔴 [각 알고리즘이 왜 존재하는가]

버블/선택/삽입 정렬 — O(n²):
  단순하다. 교육용. 데이터가 작으면(n < 50) 오버헤드가 적어 실제로 빠름.
  삽입 정렬: 거의 정렬된 데이터에서 O(n) — 이 특성 때문에 실무에서도 사용됨.

머지 정렬 — O(n log n) 보장:
  항상 O(n log n). 최악이 없다. 안정 정렬.
  대가: O(n) 추가 메모리 (합병 시 임시 배열 필요).
  연결 리스트 정렬에 이상적 (추가 메모리 불필요).

퀵 정렬 — 실전에서 가장 빠름:
  평균 O(n log n), 최악 O(n²) (피벗이 최소/최대일 때).
  왜 실전에서 빠른가:
    in-place (추가 메모리 O(log n) — 재귀 스택만)
    캐시 친화적 (연속 메모리 순회)
    상수가 작다 (머지 정렬 대비)
  
  최악 방지: 랜덤 피벗 선택 → 기대 O(n log n)

  왜 피벗이 핵심인가:
    좋은 피벗: 배열을 거의 절반으로 나눔 → 레벨 log n개
    나쁜 피벗: 한쪽이 거의 0 → 레벨 n개 → O(n²)
    
    랜덤 피벗이면 "기대" 분할 비율이 좋아서 O(n log n)

힙 정렬 — O(n log n) 보장 + in-place:
  머지 정렬의 "추가 메모리" + 퀵 정렬의 "최악 O(n²)" 둘 다 해결.
  그런데 왜 퀵 정렬만큼 안 쓰이는가:
    캐시 비친화적 (힙의 부모-자식 접근이 비연속적)
    실제 상수가 퀵 정렬보다 큼

기수 정렬 — O(d·n): 비교를 안 한다!
  비교 기반이 아님 → Ω(n log n) 하한에 안 걸림!
  d = 자릿수 (또는 문자열 길이). d가 상수이면 O(n).
  
  왜 항상 쓰지 않는가:
    정수/문자열 등 "자릿수 분해"가 가능한 데이터에만 적용
    범용성이 떨어짐. 비교 기반은 어떤 데이터에든 적용 가능.
```

### 4.3 정렬 알고리즘 선택 — 실무 기준

```
  ┌──────────────┬──────────────────────────────────┐
  │ 상황          │ 선택                              │
  ├──────────────┼──────────────────────────────────┤
  │ 범용 정렬     │ 퀵 정렬 (또는 인트로정렬)          │
  │ 안정성 필요   │ 머지 정렬 또는 팀소트(Timsort)     │
  │ 메모리 제한   │ 힙 정렬 (in-place 보장)           │
  │ 거의 정렬됨   │ 삽입 정렬 (O(n))                  │
  │ 정수 데이터   │ 기수 정렬 (O(n))                  │
  │ 외부 정렬     │ 머지 정렬 (순차 접근 패턴)          │
  └──────────────┴──────────────────────────────────┘

  Python sorted(): Timsort (머지 + 삽입의 하이브리드)
  Java Arrays.sort(): 기본형은 듀얼 피벗 퀵, 객체는 Timsort
  C++ std::sort(): 인트로정렬 (퀵 + 힙 + 삽입의 하이브리드)
```

## 5. 탐색 알고리즘

### 5.1 이진 탐색 — "반씩 줄이기"의 원형

```
🔴 [원리] 정렬된 배열에서:
  중간값과 비교 → 찾으면 끝, 작으면 왼쪽 절반, 크면 오른쪽 절반
  
  매번 탐색 범위가 절반 → log₂ n번이면 끝 → O(log n)

왜 정렬이 전제인가:
  "중간값보다 작으면 왼쪽에 있다"는 보장이 정렬에서 나온다.
  정렬 안 됐으면 이 보장이 없다 → 절반을 버릴 수 없다.

🔵 [CS 연결]
  파라메트릭 서치: "조건을 만족하는 최소/최대값 찾기"
    → 결정 문제로 변환 + 이진 탐색
    예: "K 시간 안에 배달 가능한가?" → 이진 탐색으로 최소 K를 찾기
  
  Lower/Upper Bound:
    Lower: 값 이상인 첫 위치
    Upper: 값 초과인 첫 위치
    → C++ lower_bound, Python bisect_left
```

## 6. 동적 프로그래밍 — "같은 일을 두 번 하지 마라"

### 6.1 DP의 원리 — 왜 이것이 마법처럼 빠른가

```
🔴 [원리] 동적 프로그래밍의 두 가지 조건:

  (1) 최적 부분 구조 (Optimal Substructure):
      큰 문제의 최적해가 작은 문제의 최적해를 포함한다.

  (2) 중복 부분 문제 (Overlapping Subproblems):
      같은 부분 문제가 여러 번 반복해서 나타난다.

왜 마법처럼 빠른가 — 피보나치로 이해:

  순수 재귀:
  F(5) = F(4) + F(3)
       = (F(3)+F(2)) + (F(2)+F(1))
       = ((F(2)+F(1))+F(2)) + (F(2)+F(1))
  
  F(2)가 3번, F(1)이 2번 중복 계산된다!
  n이 커지면 중복이 기하급수적 → O(2ⁿ)

  DP (메모이제이션):
  F(5) → F(4) 계산 (F(3) 필요 → 계산 후 저장)
       → F(3) 필요 → 이미 저장되어 있음 → 즉시 반환!
  
  각 F(k)를 딱 한 번만 계산 → O(n)
  
  지수 시간 → 선형 시간! 이것이 DP의 힘이다.
```

### 6.2 Top-down vs Bottom-up — 같은 것의 두 가지 구현

```
Top-down (메모이제이션):
  재귀 + 결과 캐싱. "필요할 때 계산하고 저장"
  
  memo = {}
  def fib(n):
      if n in memo: return memo[n]    # 이미 계산했으면 반환
      if n <= 1: return n
      memo[n] = fib(n-1) + fib(n-2)  # 계산 후 저장
      return memo[n]

Bottom-up (타뷸레이션):
  작은 것부터 순서대로 채운다. "테이블을 바닥부터 쌓기"
  
  dp = [0] * (n+1)
  dp[1] = 1
  for i in range(2, n+1):
      dp[i] = dp[i-1] + dp[i-2]

두 방법은 같은 점화식을 다른 순서로 계산한다.
Top-down: 큰 문제에서 시작, 필요한 것만 계산 (lazy)
Bottom-up: 작은 것부터 전부 계산 (eager), 재귀 오버헤드 없음
```

### 6.3 대표적 DP 문제 — 각각 왜 DP인가

```
🔵 배낭 문제 (0/1 Knapsack):
  무게 제한 W인 배낭에 가치를 최대화하도록 물건 선택
  
  왜 DP: 물건 i를 넣거나 안 넣거나 → 남은 용량에 대한 부분 문제
  dp[i][w] = max(dp[i-1][w], dp[i-1][w-wᵢ] + vᵢ)
  
  O(nW) — "의사 다항 시간" (W가 비트 수에 지수적이면 지수 시간)

🔵 최장 공통 부분 수열 (LCS):
  두 문자열의 가장 긴 공통 부분 수열
  
  왜 DP: 마지막 문자가 같으면 양쪽을 줄이고, 다르면 한쪽씩 줄여서 비교
  dp[i][j] = dp[i-1][j-1]+1   (같으면)
           = max(dp[i-1][j], dp[i][j-1])  (다르면)
  O(mn)

🔵 최장 증가 부분 수열 (LIS):
  가장 긴 순증가하는 부분 수열의 길이
  O(n²) DP, O(n log n) 이진 탐색 최적화

🔵 편집 거리 (Edit Distance):
  한 문자열을 다른 문자열로 바꾸는 최소 연산 수 (삽입, 삭제, 교체)
  dp[i][j] = 첫 i글자와 첫 j글자의 편집 거리
  O(mn)
  🔵 NLP의 맞춤법 교정, DNA 서열 비교에 사용
```

## 7. 그리디 — "지금 당장 최선을 선택"

### 7.1 그리디 원리 — 왜 때로는 이것이 최적인가

```
🔴 [원리] 그리디 (Greedy):
  매 단계에서 "지금 가장 좋아 보이는 선택"을 한다.
  한 번 선택하면 되돌리지 않는다.

왜 때로는 최적인가:
  그리디 선택 속성 (Greedy Choice Property):
    "전체 최적해에 반드시 지역 최적 선택이 포함된다"
    
  이 성질이 있으면 → 탐욕적 선택이 전체 최적을 보장
  이 성질이 없으면 → 그리디는 최적이 아닌 해를 줄 수 있다

DP와의 차이:
  DP: 모든 부분 문제를 풀고 최적을 선택 → 항상 최적, 느릴 수 있음
  그리디: 한 번의 선택으로 부분 문제를 하나만 남김 → 빠르지만, 최적 보장 조건 필요
```

### 7.2 대표적 그리디 알고리즘

```
🔵 활동 선택 문제:
  겹치지 않는 최대 활동 수 선택
  전략: 끝나는 시간이 가장 빠른 활동을 먼저 선택
  
  왜 이것이 최적인가:
    빨리 끝나는 것을 선택하면 → 뒤에 남는 시간이 최대
    → 더 많은 활동을 배치할 여지가 최대
    → 다른 어떤 선택도 이보다 좋을 수 없다 (교환 논법으로 증명)

🔵 허프만 코딩 (Ch.08에서 상세):
  빈도가 낮은 두 기호를 반복적으로 합치기
  그리디 선택: "지금 가장 빈도가 낮은 두 개를 합치면 전체 최적"

🔵 크루스칼/프림 (MST): §8에서 다룸
🔵 다익스트라 (최단 경로): §8에서 다룸

그리디가 안 되는 예시:
  0/1 배낭 문제: 가치/무게 비율이 가장 높은 것을 먼저 넣으면?
  → 최적이 아닐 수 있다! (단위 가치가 높지만 무거워서 다른 좋은 것을 못 넣을 수 있음)
  → DP를 써야 한다.
```

## 8. 그래프 알고리즘 — CS의 가장 풍부한 알고리즘 분야

### 8.1 BFS와 DFS — 두 가지 근본 탐색

```
🔴 BFS (너비 우선 탐색): 큐 사용
  "가까운 것부터" — 레벨별로 탐색
  
  시작 → 거리 1인 노드들 → 거리 2인 노드들 → ...
  
  특성: 비가중 그래프에서 최단 경로를 보장한다!
  왜: 거리 순서대로 방문하므로, 처음 방문한 경로가 최단.
  
  복잡도: O(V + E)

🔴 DFS (깊이 우선 탐색): 스택(재귀) 사용
  "한 방향으로 끝까지" — 막다른 길에서 되돌아옴
  
  특성: 사이클 감지, 위상 정렬, 연결 요소, SCC 등에 사용
  왜 DFS가 이런 것들에 적합한가:
    "끝까지 가봐야 아는 것"들 — 사이클이 있는지, 모든 경로를 다 탐색했는지
    → DFS는 한 경로를 완전히 탐색한 후 다음으로 넘어간다
  
  복잡도: O(V + E)

BFS vs DFS 선택 기준:
  최단 경로 필요? → BFS
  모든 경로 탐색 / 사이클 감지? → DFS
  메모리 제한? → DFS (스택 = O(높이)), BFS (큐 = O(너비, 최악 O(V)))
```

### 8.2 최단 경로 — 왜 여러 알고리즘이 필요한가

```
각 알고리즘은 서로 다른 조건에서 최적이다:

🔴 다익스트라 (Dijkstra):
  조건: 음이 아닌 가중치
  원리: "아직 확정되지 않은 노드 중 가장 가까운 것을 확정"
  복잡도: O((V+E) log V) (최소 힙 사용)

  왜 이것이 작동하는가:
    그리디 선택: 가장 가까운 미확정 노드의 거리는 더 이상 줄어들 수 없다.
    왜? 다른 경로를 통하면 중간 노드의 거리 ≥ 현재 최소 거리 (음이 아닌 가중치이므로).
    → 한번 확정하면 되돌릴 필요 없다 = 그리디가 통한다.

  음의 가중치가 있으면 왜 안 되는가:
    음의 간선을 통하면 이미 확정한 거리가 줄어들 수 있다!
    → 그리디 선택이 무효화된다.

🔴 벨만-포드 (Bellman-Ford):
  조건: 음의 가중치 허용 (음수 사이클 감지 가능)
  원리: 모든 간선을 V-1번 반복하여 이완(relaxation)
  복잡도: O(VE)

  왜 V-1번:
    최단 경로는 최대 V-1개의 간선을 가진다 (V개 노드, 사이클 없으면).
    매 반복마다 최소 하나의 노드의 최단 거리가 확정된다.
    → V-1번이면 모든 노드가 확정.

  음수 사이클 감지:
    V번째 반복에서도 거리가 줄어드는 노드가 있으면 → 음수 사이클 존재!
    (사이클을 돌수록 거리가 계속 줄어드므로)

🔴 플로이드-워셜 (Floyd-Warshall):
  조건: 모든 쌍 최단 경로 (음수 가중치 허용, 음수 사이클 불가)
  원리: dp[i][j][k] = "정점 1~k만 경유하여 i→j의 최단 거리"
  복잡도: O(V³)

  왜 이 DP가 작동하는가:
    정점 k를 경유하거나 안 하거나:
    dp[i][j][k] = min(dp[i][j][k-1], dp[i][k][k-1] + dp[k][j][k-1])
    
    경유 정점을 하나씩 추가하면서 최단 거리를 갱신해 나간다.
```

### 8.3 최소 신장 트리 — "가장 싸게 모두 연결"

```
🔴 크루스칼 (Kruskal):
  전략: 간선을 가중치 순으로 정렬 → 사이클을 만들지 않는 간선만 추가
  도구: 유니온-파인드로 사이클 판별 (Ch.09)
  복잡도: O(E log E)
  
  왜 이것이 최적인가 (그리디 정당성):
    컷 성질(Cut Property): 그래프를 둘로 나누는 어떤 컷에서든,
    컷을 가로지르는 가장 가벼운 간선은 반드시 MST에 포함된다.
    → 가벼운 간선부터 선택하면 이 성질을 자동으로 만족.

🔴 프림 (Prim):
  전략: 한 정점에서 시작, 현재 트리에서 가장 가까운 정점을 반복 추가
  도구: 최소 힙 (우선순위 큐)
  복잡도: O((V+E) log V)
  
  다익스트라와 유사한 구조! (그리디 + 최소 힙)
  차이: 다익스트라는 "시작점에서의 거리", 프림은 "트리에서의 거리"

크루스칼 vs 프림:
  희소 그래프 (E ≈ V): 크루스칼이 유리
  밀집 그래프 (E ≈ V²): 프림이 유리
```

### 8.4 위상 정렬 — "선행 조건을 지키는 순서"

```
🔴 [정의] 방향 비순환 그래프(DAG)에서:
  모든 간선 (u, v)에 대해 u가 v보다 앞에 오는 순서.

방법 1: 칸 알고리즘 (BFS 기반)
  진입 차수가 0인 노드를 큐에 넣고, 처리하면서 이웃의 진입 차수 감소
  
방법 2: DFS 기반
  DFS 후위 순서의 역순 = 위상 정렬

🔵 [CS 연결]
  빌드 시스템: make, gradle의 의존성 해결
  대학 수강 과목: 선수과목 순서 결정
  컴파일러: 명령어 스케줄링
  스프레드시트: 셀 계산 순서 (A1=B1+C1이면 B1, C1 먼저)
```

## 9. 문자열 알고리즘

### 9.1 패턴 매칭 — 왜 순진한 방법은 느린가

```
텍스트 T (길이 n)에서 패턴 P (길이 m)를 찾기

순진한 방법: O(nm)
  모든 위치에서 P를 비교 → n개 위치 × m개 문자 비교

🔴 KMP (Knuth-Morris-Pratt): O(n + m)
  핵심: 불일치가 발생했을 때, 이미 비교한 정보를 재활용한다.
  실패 함수(failure function): "지금까지 매칭된 접두사 중 접미사이기도 한 가장 긴 것"
  
  왜 빠른가:
    순진한 방법은 불일치 시 처음부터 다시 비교.
    KMP는 "이미 매칭된 부분에서 다시 시작할 수 있는 위치"를 미리 계산.
    → 텍스트의 각 문자를 최대 2번만 비교 → O(n)

🔴 라빈-카프 (Rabin-Karp): 평균 O(n + m)
  핵심: 문자열 비교 대신 해시값을 비교한다.
  롤링 해시: 이전 해시에서 O(1)로 다음 해시 계산
  → 해시가 같으면 문자열 비교 (거짓 양성 가능)
  → 다중 패턴 매칭에 유리
```

## 10. 백트래킹 — "시도하고, 안 되면 되돌린다"

```
🔴 [원리] 백트래킹:
  가능한 해를 탐색하되, 조건을 위반하면 즉시 되돌아간다 (가지치기, pruning).

  전체 탐색보다 빠른 이유:
    "이 선택은 절대 답이 될 수 없다"는 것을 조기에 판단하여
    그 아래의 모든 탐색을 건너뛴다.

  탐색 트리:
                  (시작)
              ╱     │     ╲
            (A)    (B)    (C) ← 위반! 가지치기(이 아래 전부 건너뜀)
           ╱  ╲    │
         (A,B)(A,C)(B,A)
          │    ↑    │
          ✓  위반!   ✓

예시: N-Queen 문제
  n×n 체스판에 n개의 퀸을 서로 공격하지 못하게 배치
  
  행마다 하나씩 배치 → 열 선택 → 대각선 충돌 검사
  충돌하면 그 행에서 다른 열 시도 → 모든 열이 안 되면 이전 행으로 되돌아감

🔵 [CS 연결]
  스도쿠 풀기, 그래프 색칠, 부분집합 합 문제
  컴파일러의 구문 분석 (일부 파서)
  SAT 솔버의 기본 전략 (DPLL)
```

## 11. 랜덤 알고리즘 — "운"을 활용하기

```
🔴 [원리] 알고리즘에 무작위성을 도입하여 성능이나 단순성을 얻는다.

두 종류:
  라스베이거스(Las Vegas): 항상 정확한 답, 실행 시간이 랜덤
    예: 랜덤 퀵소트 — 항상 정렬됨, 기대 O(n log n)

  몬테카를로(Monte Carlo): 실행 시간이 확정적, 답이 확률적으로 정확
    예: 밀러-라빈 소수 판정 — O(k log²n), 오류 확률 < 4⁻ᵏ

왜 랜덤이 유용한가:
  최악의 입력이 없다! 적대적 입력이 만들어질 수 없다.
  확률적으로 좋은 성능이 보장된다.
  종종 결정적 알고리즘보다 훨씬 단순하다.

🔵 [CS 연결]
  해시 함수의 유니버설 해싱: 랜덤하게 해시 함수를 선택
  Skip list: 랜덤 레벨 할당 → 기대 O(log n) 검색
  랜덤 포레스트: 무작위 특성 선택으로 과적합 방지
```

## 12. 근사 알고리즘 — "최적 대신 거의 최적"

```
🔴 [원리] NP-hard 문제에 대해:
  최적해를 포기하고, "최적의 c배 이내"인 해를 다항 시간에 구한다.

  근사 비율: c = (근사 알고리즘의 해) / (최적해) ≤ 보장 상수

예시:
  정점 커버(Vertex Cover): 2-근사 (최적의 2배 이내)
    전략: 임의의 간선 선택 → 양쪽 끝점을 모두 포함 → 반복
    왜 2배 이내: 최적해도 각 간선의 최소 한쪽을 포함해야 하므로.

  TSP (메트릭): 1.5-근사 (크리스토피데스 알고리즘)
  
왜 근사가 필요한가:
  NP-hard 문제는 정확한 해를 구하려면 지수 시간.
  실용적 크기의 입력에서 "합리적 시간에 괜찮은 답"이 필요하다.
```

## 13. NP-완전 이론 — "풀 수 없는 것"의 경계

### 13.1 P, NP, NP-완전 — 왜 이 구분이 중요한가

```
🔴 [정의]

  P:   다항 시간에 "풀 수 있는" 문제들의 집합
       예: 정렬, 최단 경로, 이진 탐색

  NP:  다항 시간에 "검증할 수 있는" 문제들의 집합
       예: 해밀턴 경로 — 경로가 주어지면 O(n)에 맞는지 확인 가능
           그러나 경로를 찾는 것은 지수 시간일 수 있음

  P ⊆ NP (풀 수 있으면 검증도 가능하니까)

  NP-hard: "NP의 모든 문제만큼 어려운" 문제
           NP의 어떤 문제든 이 문제로 다항 환원 가능

  NP-complete: NP ∩ NP-hard
               NP에 속하면서 NP만큼 어려운 문제
               → "NP에서 가장 어려운 문제들"

               NP-complete 중 하나라도 다항 시간에 풀리면
               → NP의 모든 문제가 다항 시간에 풀린다
               → P = NP!
```

### 13.2 P = NP? — CS 최대의 미해결 문제

```
P = NP인가?

  직관적 의미: "쉽게 검증할 수 있는 것은 쉽게 풀 수도 있는가?"
  
  스도쿠 비유:
    완성된 스도쿠가 맞는지 확인하는 것은 쉽다 (검증, NP)
    빈 스도쿠를 푸는 것은 어렵다 (풀기, P인가?)
    
    검증이 쉬우면 풀기도 쉬운가? → 대부분의 전문가는 "아니오"라고 믿음
    그러나 아직 증명되지 않았다.

  밀레니엄 상금: 100만 달러 (클레이 수학 연구소)

왜 이것이 중요한가:
  P ≠ NP이면:
    → 암호학이 안전 (RSA 깨는 것이 어렵다는 보장)
    → 근사 알고리즘과 휴리스틱이 필요한 세상
    → 현재 CS의 기반이 유지됨

  P = NP이면:
    → 모든 NP 문제를 효율적으로 풀 수 있다
    → 대부분의 암호가 깨진다
    → AI, 약물 설계, 물류 등 혁명적 변화
    → (대부분의 전문가는 이 가능성이 매우 낮다고 봄)
```

### 13.3 대표적 NP-complete 문제들

```
🔴 [외워야 할 NP-complete 문제들]

  SAT (Boolean Satisfiability): 부울 식을 참으로 만드는 배정이 있는가?
    → 최초로 NP-complete임이 증명됨 (쿡-레빈 정리, 1971)

  3-SAT: 각 절(clause)이 3개의 리터럴로 구성된 SAT
  
  해밀턴 경로/회로: 모든 정점을 정확히 한 번 방문하는 경로/회로
  
  TSP (외판원 문제): 가장 짧은 해밀턴 회로
  
  그래프 색칠 (k ≥ 3): k개 색으로 인접한 정점이 다른 색이 되게 칠하기
  
  부분집합 합: 집합에서 합이 정확히 S인 부분집합이 있는가?
  
  클리크: 크기 k인 완전 부분 그래프가 있는가?
  
  정점 커버: k개 이하의 정점으로 모든 간선을 커버할 수 있는가?

다항 환원 (Polynomial Reduction):
  A ≤_p B: "A를 B로 다항 시간에 변환할 수 있다"
  → B를 풀 수 있으면 A도 풀 수 있다
  → B가 A만큼 어렵다 (또는 더 어렵다)

  3-SAT → 그래프 색칠 → ... → 모든 NP-complete 문제가 서로 환원 가능!
  → 하나를 풀면 전부 풀린다. 이것이 "NP-complete"의 의미.
```

## 15. 정리 — 알고리즘을 관통하는 원리

```
[원리 1] 복잡도 분석: 상수와 하위 항을 무시하고 성장 속도의 본질을 본다.
  → O(n log n) vs O(n²)가 실용적 차이를 결정한다.

[원리 2] 분할 정복: "n을 반으로 줄이는 것을 log n번" = O(n log n)의 원천.
  → 머지 정렬, 퀵 정렬, FFT, 이진 탐색의 공통 원리.

[원리 3] DP: "같은 부분 문제를 한 번만 풀고 결과를 저장" → 지수→다항.
  → 최적 부분 구조 + 중복 부분 문제가 조건.

[원리 4] 그리디: "지역 최적 = 전역 최적"일 때만 사용.
  → 그리디 선택 속성의 증명이 필수.

[원리 5] 그래프: BFS = 최단 경로(비가중), DFS = 구조 탐색.
  → 다익스트라는 그리디, 벨만-포드는 DP, 플로이드-워셜은 DP.

[원리 6] NP-완전: 다항 시간 풀이가 알려지지 않은 문제 집합.
  → 하나를 풀면 전부 풀린다. 아직 아무도 못 풀었다.

[원리 7] 비교 기반 정렬의 하한 Ω(n log n): 정보이론에서 유도.
  → 이 하한을 깨려면 비교가 아닌 다른 연산을 써야 한다.

외워야 할 것:
  🔴 복잡도 계층: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
  🔴 마스터 정리의 3가지 케이스
  🔴 주요 정렬의 시간/공간/안정성
  🔴 다익스트라: 음의 가중치 불가, O((V+E) log V)
  🔴 벨만-포드: 음의 가중치 가능, O(VE), 음수 사이클 감지
  🔴 NP, NP-hard, NP-complete의 정의
  🔴 대표적 NP-complete 문제 목록

유도할 수 있는 것:
  🟢 머지 정렬이 O(n log n)인 이유 (재귀 트리 분석)
  🟢 비교 기반 정렬의 하한 (결정 트리 + log n!)
  🟢 다익스트라에서 음의 가중치가 안 되는 이유
  🟢 벨만-포드에서 V-1번 반복하는 이유
  🟢 DP의 시간 복잡도 = (부분 문제 수) × (각 부분 문제 비용)
```
