## 1. 추론이란 — 왜 이것이 모든 학문의 기반인가

### 1.1 추론의 세 가지 유형

```
🔴 [정의] 추론(reasoning): 알려진 정보(전제)에서 새로운 정보(결론)를 이끌어내는 과정.

세 가지 근본적 추론 유형이 있다:

  (1) 연역 (Deduction):    일반 원칙 → 구체적 결론   "확실"
  (2) 귀납 (Induction):    구체적 관찰 → 일반 원칙   "개연적"
  (3) 귀추 (Abduction):    결과 관찰 → 최선의 설명   "추측적"

각각이 무엇이고 왜 다른지:
```

### 1.2 연역 추론 — "전제가 참이면 결론도 반드시 참"

```
🔴 [정의] 연역(deduction):
  일반적 원칙(전제)에서 논리적 필연성을 가진 결론을 도출.
  전제가 참이면 결론은 반드시 참이다. "100% 확실."

  구조:
    전제 1: 모든 사람은 죽는다.
    전제 2: 소크라테스는 사람이다.
    ∴ 결론: 소크라테스는 죽는다.

  왜 반드시 참인가:
    "모든 사람"이 죽는다고 했으므로, 사람인 소크라테스도 예외가 아니다.
    결론은 이미 전제 안에 "포함"되어 있다. 새로운 정보를 만드는 것이 아니라
    전제에 숨어 있는 정보를 꺼내는 것이다.

  강점: 결론의 확실성
  한계: 전제가 거짓이면 결론도 보장 못 함. 전제 자체의 참은 연역이 보장하지 않음.

🔵 [CS 연결]
  수학적 증명: 공리(전제) → 정리(결론). 연역적 체계.
  프로그램 검증: 전제(사전 조건) → 실행 → 결론(사후 조건). Hoare Logic (Ch.16).
  타입 검사: 타입 규칙(전제) → "이 프로그램은 타입 안전하다"(결론).
  SQL WHERE: 조건(전제) → 행 선택(결론).
```

### 1.3 귀납 추론 — "관찰에서 일반화"

```
🔴 [정의] 귀납(induction, 여기서는 과학적 귀납):
  구체적 관찰들로부터 일반적 원칙을 "추정"한다.
  반드시 참은 아니다. "개연적(probable)."

  주의: 수학적 귀납법(mathematical induction)과 다르다!
  수학적 귀납법은 연역적 증명 방법이다 (§4에서 다룸).
  여기서의 귀납은 "과학적/경험적 귀납"이다.

  구조:
    관찰: 백조 1을 봤더니 희다.
    관찰: 백조 2를 봤더니 희다.
    관찰: 백조 3을 봤더니 희다.
    ... (1000마리 모두 희다)
    ∴ 결론: 모든 백조는 희다.  ← 개연적이지만, 확실하지 않다!

  왜 확실하지 않은가:
    호주에 검은 백조가 발견되었다 (1697년).
    1000마리를 봐서 "모든"이라고 할 수 없다. 하나의 반례로 무너진다.
    이것이 "귀납의 문제" (Problem of Induction, Hume).

  그런데 왜 귀납을 쓰는가:
    과학의 대부분이 귀납이다!
    "태양이 내일 뜰 것이다" — 수십억 번의 관찰에 기반한 귀납.
    100% 확실하지 않지만, 현실적으로 충분히 신뢰할 수 있다.
    → "확실성"이 아니라 "신뢰도"의 문제.

🔵 [CS 연결]
  머신러닝: 훈련 데이터(관찰)에서 일반적 패턴(모델)을 학습 = 귀납!
    "이 1000장의 고양이 사진을 보았으므로, 새 이미지도 분류할 수 있다"
    → 훈련 데이터에 없는 입력에서 실패할 수 있다 = 귀납의 한계 = 과적합(overfitting)!
  
  테스팅: "100가지 테스트 케이스를 통과했으므로 버그가 없다" = 귀납적 주장
    → 101번째에서 실패할 수 있다. 테스팅은 버그의 부재를 증명하지 않는다!
    (Dijkstra: "테스팅은 버그의 존재를 보여줄 수 있지만, 부재를 보여줄 수 없다")
```

### 1.4 귀추 추론 — "최선의 설명 추론"

```
🔴 [정의] 귀추(abduction, inference to the best explanation):
  관찰된 결과에 대해 가장 그럴듯한 원인/설명을 추론한다.

  구조:
    관찰: 잔디가 젖어 있다.
    가능한 설명 1: 비가 왔다.
    가능한 설명 2: 스프링클러가 작동했다.
    가능한 설명 3: 이슬이 맺혔다.
    ∴ 결론: 비가 왔을 가능성이 가장 높다. (다른 증거와 종합하여)

  왜 확실하지 않은가:
    여러 원인이 같은 결과를 만들 수 있다.
    "가장 그럴듯한" 설명을 선택하지만, 틀릴 수 있다.

  연역·귀납과의 관계:
    연역:  규칙 + 사례 → 결과  (확실)
    귀납:  사례 + 결과 → 규칙  (개연적)
    귀추:  규칙 + 결과 → 사례  (추측적)

    모든 사람은 죽는다 (규칙) + 소크라테스는 사람이다 (사례) → 소크라테스는 죽는다 (결과) : 연역
    백조 1,2,3이 희다 (사례+결과) → 모든 백조는 희다 (규칙) : 귀납
    모든 사람은 죽는다 (규칙) + 소크라테스가 죽었다 (결과) → 소크라테스는 사람이었다 (사례) : 귀추

🔵 [CS 연결]
  디버깅: 프로그램이 오류를 냄(결과) → 어떤 버그가 원인인가?(사례) = 귀추!
  의료 진단: 증상(결과) → 어떤 질병인가?(사례) = 귀추
  베이즈 추론: P(원인|결과) ∝ P(결과|원인) · P(원인) → 확률적 귀추! (Ch.03)
    → 베이즈 정리는 귀추를 수학적으로 정밀하게 만든 것이다.
```

## 2. 연역적 추론의 형식 — 유효한 논증 형태

### 2.1 왜 "형식"이 중요한가

```
추론이 올바른지 판단하려면, 내용이 아니라 구조(형식)를 봐야 한다.

  "모든 고양이는 파충류이다. 모든 파충류는 날 수 있다. ∴ 모든 고양이는 날 수 있다."
  
  이것은 내용은 거짓이지만, 논증 형식은 유효(valid)하다!
  전제가 참이었다면 결론도 반드시 참이었을 것이다.
  
  유효성(validity): 형식이 올바른가 → 전제가 참이면 결론이 반드시 참
  건전성(soundness): 유효 + 전제가 실제로 참 → 결론도 실제로 참
```

### 2.2 핵심 논증 형식들 — 왜 이것들이 기본인가

```
🔴 [외워야 할 유효한 논증 형식들]

(1) 전건 긍정 (Modus Ponens): 가장 기본!
    p → q      "p이면 q이다"
    p           "p이다"
    ∴ q        "따라서 q이다"
    
    예: "비가 오면 땅이 젖는다. 비가 온다. ∴ 땅이 젖는다."
    
    왜 유효한가: p → q에서 p가 참이면 q가 거짓일 수 없다 (조건문의 정의).

(2) 후건 부정 (Modus Tollens): 대우 원리!
    p → q      "p이면 q이다"
    ¬q          "q가 아니다"
    ∴ ¬p       "따라서 p가 아니다"
    
    예: "비가 오면 땅이 젖는다. 땅이 안 젖었다. ∴ 비가 안 왔다."
    
    왜 유효한가: p → q ≡ ¬q → ¬p (대우). 대우에 전건 긍정을 적용한 것.

(3) 가설적 삼단논법 (Hypothetical Syllogism): 체인!
    p → q
    q → r
    ∴ p → r
    
    예: "비가 오면 땅이 젖고, 땅이 젖으면 미끄럽다. ∴ 비가 오면 미끄럽다."
    
    왜 유효한가: 조건의 연쇄. p가 참이면 q가 참, q가 참이면 r이 참.
    🔵 프로그래밍: 함수 합성! f: A→B, g: B→C → g∘f: A→C

(4) 선언적 삼단논법 (Disjunctive Syllogism): 소거!
    p ∨ q      "p 또는 q이다"
    ¬p          "p가 아니다"
    ∴ q        "따라서 q이다"
    
    왜 유효: 둘 중 하나인데 하나가 아니면, 나머지가 참.

(5) 구성적 딜레마 (Constructive Dilemma):
    p → q
    r → s
    p ∨ r
    ∴ q ∨ s
    
    "어느 쪽이든 좋은 결과" (또는 "어느 쪽이든 나쁜 결과")
```

### 2.3 무효한 논증 형식 — 흔한 오류

```
🔴 [외워야 할 논리적 오류 — 유효해 보이지만 유효하지 않은 것!]

(1) 후건 긍정의 오류 (Affirming the Consequent):
    p → q
    q
    ∴ p  ← 무효!!
    
    "비가 오면 땅이 젖는다. 땅이 젖었다. ∴ 비가 왔다."
    → 스프링클러 때문일 수도 있다! q가 참이라고 p가 참인 것은 아니다.
    
    왜 오류인가: p → q에서 q가 참이어도, p가 아닌 다른 원인으로 q가 참일 수 있다.
    
    🔵 디버깅에서의 함정:
    "이 버그가 있으면 이 증상이 나타난다. 이 증상이 나타났다. ∴ 이 버그가 원인이다."
    → 다른 버그가 같은 증상을 만들 수 있다!

(2) 전건 부정의 오류 (Denying the Antecedent):
    p → q
    ¬p
    ∴ ¬q  ← 무효!!
    
    "비가 오면 땅이 젖는다. 비가 안 왔다. ∴ 땅이 안 젖었다."
    → 다른 이유로 젖었을 수 있다!
    
    왜 오류인가: p가 q의 유일한 원인이라는 가정이 없다.

(3) 성급한 일반화 (Hasty Generalization):
    "내가 만난 3명의 프로그래머는 안경을 썼다. ∴ 모든 프로그래머는 안경을 쓴다."
    → 표본이 너무 작다. 귀납의 오용.
    🔵 ML: 과적합과 같은 오류. 훈련 데이터의 특성을 전체에 일반화.

(4) 거짓 딜레마 (False Dilemma):
    "당신은 우리 편이거나 적이다." → 중간 선택지가 있을 수 있다!
    🔵 이진 분류만으로 다중 클래스 문제를 다루면 생기는 오류와 유사.

(5) 순환 논증 (Circular Reasoning / Begging the Question):
    결론을 전제로 사용하는 것.
    "신은 존재한다. 왜냐하면 경전에 그렇게 쓰여 있고, 경전은 신의 말씀이니까."
    → 전제가 결론을 이미 가정하고 있다.
```

## 3. 증명 기법 — CS에서 쓰이는 핵심 방법들

### 3.1 직접 증명 — 가장 직관적

```
🔴 [방법] p → q를 증명하려면:
  p가 참이라고 가정 → 논리적 단계를 밟아 → q가 참임을 보인다.

예시: "n이 짝수이면 n²도 짝수이다"
  가정: n은 짝수 → n = 2k (어떤 정수 k)
  n² = (2k)² = 4k² = 2(2k²)
  2k²는 정수이므로 n² = 2(정수) → n²은 짝수. □

  왜 이것이 증명인가:
    출발점(전제)에서 도착점(결론)까지의 모든 단계가
    이미 증명된 정리나 정의에 의해 정당화된다.
    체인의 모든 고리가 확실하므로, 전체 체인도 확실하다.

🔵 [CS 연결]
  알고리즘 정당성의 직접 증명:
    "이 정렬 알고리즘의 출력은 항상 정렬되어 있다"
    → 루프 불변식(loop invariant)을 세우고, 각 반복에서 유지됨을 보인다.
```

### 3.2 대우 증명 — 정면이 어려울 때

```
🔴 [방법] p → q 대신, 동치인 ¬q → ¬p를 증명한다.

왜 동치인가:
  p → q ≡ ¬q → ¬p (대우, Ch.04에서 증명)
  하나를 증명하면 다른 것도 자동으로 증명된다.

예시: "n²이 짝수이면 n도 짝수이다"
  직접 증명이 어렵다 (n² = 2k에서 n = ?를 바로 구하기 어려움).
  
  대우: "n이 홀수이면 n²도 홀수이다"
  가정: n = 2k + 1
  n² = (2k+1)² = 4k² + 4k + 1 = 2(2k²+2k) + 1 → 홀수. □
  
  대우가 참이므로, 원래 명제도 참. □

  왜 대우가 더 쉬운 경우가 있는가:
    "n²이 짝수"라는 가정에서 출발하면 n에 대해 아는 것이 적다.
    "n이 홀수"라는 가정에서 출발하면 n = 2k+1로 구체적으로 쓸 수 있다.
    → 더 구체적인 가정에서 출발하는 것이 진행하기 쉽다.
```

### 3.3 귀류법 — "모순으로 몰아넣기"

```
🔴 [방법] 증명하려는 것의 부정을 가정하고, 모순(contradiction)을 이끌어낸다.

  논리적 근거: ¬p가 모순을 만들면 → ¬p는 거짓 → p는 참

예시 1: "√2는 무리수이다" (Ch.04에서 다뤘으나 원리 강조)

  ¬p 가정: √2 = a/b (기약분수, 즉 gcd(a,b) = 1)
  양변 제곱: 2 = a²/b² → a² = 2b²
  → a²은 짝수 → a는 짝수 (대우 증명에서 보였음) → a = 2c
  → (2c)² = 2b² → 4c² = 2b² → b² = 2c² → b도 짝수
  → a도 짝수, b도 짝수 → gcd(a,b) ≥ 2 → 기약분수라는 가정에 모순!
  ∴ √2는 무리수. □

예시 2: "소수는 무한히 많다" (유클리드, Ch.05)
  ¬p 가정: 소수가 유한하다. 모든 소수: p₁, ..., pₙ
  N = p₁·p₂·...·pₙ + 1
  N은 어떤 pᵢ로도 나누어지지 않음 (나머지 1)
  → N은 소수이거나 목록에 없는 소인수를 가짐 → 모순!
  ∴ 소수는 무한히 많다. □

왜 귀류법이 강력한가:
  직접 증명이 어려울 때, "반대를 가정하면 세상이 무너진다"를 보이는 것이
  종종 더 쉽다. 모순은 어디서든 나올 수 있어서 창의적 여지가 크다.

🔵 [CS 연결]
  정지 문제의 결정 불가능성 (Turing, 1936):
    가정: 정지 문제를 푸는 프로그램 H가 존재한다.
    H를 이용해 자기 자신에게 적용하면 → 모순 (멈추면 안 멈추고, 안 멈추면 멈춤)
    ∴ 그런 H는 존재하지 않는다. □
    → 칸토어의 대각선 논법과 같은 구조! (Ch.07)
```

### 3.4 수학적 귀납법 — 재귀의 쌍둥이

```
🔴 [방법] 자연수에 대한 명제 P(n)을 증명:
  (1) 기저 단계 (Base case): P(0) 또는 P(1)이 참
  (2) 귀납 단계 (Inductive step): P(k) → P(k+1)
  → 모든 n ≥ 0에 대해 P(n)이 참

주의: "수학적 귀납법"은 이름에 "귀납"이 있지만 연역적 증명이다!
  → 과학적 귀납(경험적 일반화)과 완전히 다르다.
  → P(k) → P(k+1)을 "모든 k"에 대해 증명하므로 확실한 결론.

왜 이것이 유효한가:
  자연수의 정렬성 공리: 비어있지 않은 자연수 집합에는 최소 원소가 있다.
  
  만약 P(n)이 거짓인 n이 있다면, 그 중 최소인 것이 있다.
  그 최소 n은 기저 이상(P(0)은 참이므로)이고,
  P(n-1)은 참(n이 최소이므로), P(n-1) → P(n)도 참(귀납 단계)
  → P(n)도 참 → 모순!
  ∴ P(n)이 거짓인 n은 없다.

도미노 비유:
  (1) 첫 도미노를 넘어뜨린다 (기저)
  (2) 하나가 넘어지면 다음도 넘어진다 (귀납 단계)
  → 모든 도미노가 넘어진다

🔵 [CS 연결]
  재귀 알고리즘의 정당성 = 수학적 귀납법!
    기저: 입력 크기 0(또는 1)에서 올바르게 동작
    귀납: 크기 k에서 올바르면 크기 k+1에서도 올바름
    → 재귀의 구조와 귀납법의 구조가 정확히 일치한다.

  예: 머지 정렬의 정당성
    기저: 크기 1 배열은 이미 정렬됨 ✓
    귀납: 크기 k 이하에서 올바르다고 가정.
      크기 k+1 배열을 반으로 나눈다 → 각 절반은 크기 ≤ k
      → 귀납 가정에 의해 각 절반이 올바르게 정렬됨
      → merge가 두 정렬된 배열을 올바르게 합침 (별도 증명)
      → 크기 k+1에서도 올바름 ✓
    ∴ 모든 크기에서 올바르다. □
```

### 3.5 강한 귀납법 — 더 강력한 가정

```
🔴 [방법] 귀납 단계에서 P(0), P(1), ..., P(k)를 모두 가정하고 P(k+1)을 보인다.
  (일반 귀납법은 P(k)만 가정)

왜 더 강력한가:
  P(k+1)을 보이기 위해 P(k)뿐 아니라 더 이전의 결과도 사용할 수 있다.

  예: "모든 2 이상의 자연수는 소수의 곱으로 표현된다" (산술의 기본정리 일부)
    기저: 2는 소수. ✓
    강한 귀납: 2~k까지 모두 소수의 곱이라고 가정.
      k+1이 소수이면 → 자명. ✓
      k+1이 합성수이면 → k+1 = a·b (2 ≤ a, b ≤ k)
      → 강한 가정에 의해 a, b 모두 소수의 곱
      → k+1 = a·b도 소수의 곱. ✓ □

왜 일반 귀납으로는 안 되는가:
  일반 귀납은 P(k)만 알고 P(k+1)을 보여야 한다.
  k+1 = a·b에서 a와 b가 k가 아닐 수 있다 (예: k+1 = 15, a = 3, b = 5, k = 14)
  → P(3)과 P(5)가 필요하지만, 일반 귀납에서는 P(14)만 가정했다.
  → 강한 귀납이 필요!
```

### 3.6 구성적 증명 — "실제로 만들어 보인다"

```
🔴 [방법] 존재를 주장하려면, 실제로 구성하여 보인다.

  "모든 짝수는 두 정수의 합이다" → 예: n = (n/2) + (n/2). 구성 완료.

  vs 비구성적 증명: "존재하지만, 구체적으로 뭔지 모른다"
    귀류법은 종종 비구성적이다.
    "존재하지 않는다고 가정하면 모순" → 존재한다! 그런데 뭔데? → 모른다.

🔵 [CS 연결]
  구성적 증명은 알고리즘이 된다!
    "해가 존재한다"를 구성적으로 증명하면 → 그 증명 과정 자체가 해를 찾는 알고리즘.
    Curry-Howard 대응: 증명 ↔ 프로그램, 명제 ↔ 타입 (Ch.16)
    
    예: "정렬된 배열이 존재한다" → 정렬 알고리즘이 그 증명(구성)이다!
```

### 3.7 반례에 의한 반증 — "하나만 틀려도 끝"

```
🔴 [방법] "∀x P(x)"를 반증하려면, P(a)가 거짓인 a 하나만 찾으면 된다.

  주장: "모든 소수는 홀수이다"
  반례: 2는 소수이고 짝수이다.
  ∴ 주장은 거짓. □

  왜 하나로 충분한가:
    "모든 x"라고 했으므로, 예외가 단 하나라도 있으면 "모든"이 거짓.

🔵 [CS 연결]
  버그 찾기 = 반례 찾기!
    "이 프로그램은 모든 입력에 대해 올바르다" → 하나의 반례(버그)로 반증.
    프로퍼티 기반 테스팅 (QuickCheck): 랜덤 입력을 생성하여 반례를 자동 탐색.
```

### 3.8 비둘기집 원리에 의한 존재 증명

```
🔴 [방법] n+1개를 n개 상자에 넣으면 반드시 하나 이상 겹친다. (Ch.04, Ch.06)

  이것은 구성적이지 않은 존재 증명이다:
  "겹치는 상자가 존재한다" — 어느 상자인지는 모를 수 있다.

  예: "서울에 머리카락 수가 정확히 같은 두 사람이 존재한다"
    사람의 머리카락: 최대 ~150,000개 (상자 수)
    서울 인구: ~1000만 (물건 수)
    → 비둘기집 원리에 의해 같은 수를 가진 두 사람이 반드시 존재!
    → 누구인지는 모르지만, 존재한다는 것은 확실하다.
```

## 4. 추론과 증명의 전략 — 실전 가이드

### 4.1 어떤 증명 기법을 선택할 것인가

```
  ┌──────────────────────┬──────────────────────────────────┐
  │ 상황                  │ 추천 기법                          │
  ├──────────────────────┼──────────────────────────────────┤
  │ p → q를 보이고 싶다    │ 직접 증명 (p에서 출발, q에 도달)    │
  │ 직접이 어렵다          │ 대우 증명 (¬q → ¬p)              │
  │ "...이 아니다"를 보이고 │ 귀류법 (반대를 가정하고 모순)       │
  │ 자연수에 대한 명제      │ 수학적 귀납법                     │
  │ "...가 존재한다"       │ 구성적 증명 또는 비둘기집 원리       │
  │ "...가 존재하지 않는다" │ 귀류법 또는 대각선 논법             │
  │ "모든 x에 대해"가 거짓 │ 반례 하나를 제시                   │
  │ 여러 경우를 다뤄야     │ 경우 나누기 (Case Analysis)        │
  │ 재귀적 구조            │ 수학적 귀납법 (구조적 귀납법)       │
  └──────────────────────┴──────────────────────────────────┘
```

### 4.2 증명 작성의 일반 원칙

```
  (1) 증명하려는 것을 명확히 진술한다.
  (2) 사용하는 가정과 정의를 명시한다.
  (3) 각 단계가 왜 참인지 이유를 밝힌다.
  (4) 모호한 점이 없어야 한다 — "명백히", "분명히"를 남발하지 마라.
      (정말 명백하면 한 줄이라도 이유를 쓸 수 있다)
  (5) 결론에 □ 또는 QED를 표시한다.
```

## 6. 정리

```
[원리 1] 연역 = 확실한 결론. 전제 안에 포함된 정보를 꺼냄.
[원리 2] 귀납(과학적) = 개연적 일반화. ML의 본질이자 한계(과적합).
[원리 3] 귀추 = 최선의 설명 추론. 디버깅, 진단, 베이즈의 핵심.
[원리 4] 유효한 논증 형식: Modus Ponens, Modus Tollens, 삼단논법.
[원리 5] 무효한 형식(오류): 후건 긍정, 전건 부정, 성급한 일반화.
[원리 6] 증명 기법: 직접, 대우, 귀류법, 귀납법, 구성적, 반례.
[원리 7] 수학적 귀납법 = 재귀와 같은 구조. CS 증명의 핵심 도구.

외워야 할 것:
  🔴 연역/귀납/귀추의 차이와 확실성 수준
  🔴 Modus Ponens, Modus Tollens
  🔴 후건 긍정, 전건 부정의 오류
  🔴 수학적 귀납법의 구조 (기저 + 귀납 단계)
  🔴 귀류법의 구조 (부정 가정 → 모순 도출)

유도할 수 있는 것:
  🟢 대우 증명이 유효한 이유 (p→q ≡ ¬q→¬p)
  🟢 강한 귀납법이 일반 귀납법과 동치인 이유
  🟢 구성적 증명이 알고리즘이 되는 이유 (Curry-Howard)
```
