# Part A: 집합론 (Set Theory)

## 1. 왜 집합론이 수학의 기반인가

```
현대 수학의 거의 모든 것은 집합으로 정의된다:
  자연수 = 특정 집합의 체인
  함수 = 순서쌍의 집합
  관계 = 카르테시안 곱의 부분집합
  위상 = 열린 집합들의 모임

집합론 = "수학의 운영체제"
  다른 모든 수학은 집합론 위에서 돌아간다.
  (범주론이 이 위치를 대체하려는 시도가 있지만, 아직 집합론이 표준)

🔵 [CS 연결]
  타입 = 값의 집합 (int = 정수의 집합)
  DB의 테이블 = 튜플의 집합
  형식 언어 = 문자열의 집합
  → CS의 수학적 기초를 이해하려면 집합론이 필요
```

---

## 2. 소박한 집합론 vs 공리적 집합론

### 2.1 소박한 집합론의 문제 — 러셀의 역설

```
소박한 집합론: "어떤 성질을 만족하는 것들의 모임이 집합이다"

이것은 모순을 만든다:

🔴 러셀의 역설 (Russell's Paradox):
  R = { x | x ∉ x }  "자기 자신을 포함하지 않는 집합들의 집합"
  
  R ∈ R인가?
    R ∈ R이면 → 정의에 의해 R ∉ R → 모순!
    R ∉ R이면 → 정의에 의해 R ∈ R → 모순!

  어느 쪽이든 모순이다.

일상적 비유 — 이발사의 역설:
  "자기 자신을 면도하지 않는 모든 사람을 면도하는 이발사"
  이 이발사는 자기를 면도하는가? → 모순

해결책: "아무 성질이나 집합을 만들 수 있다"를 금지하고,
       엄격한 규칙(공리)을 세워서 모순이 생기지 않게 한다.
       → ZFC 공리계
```

### 2.2 ZFC 공리계 — 집합을 만드는 규칙

```
🔴 [정의 — 수학의 기반 규칙] ZFC (Zermelo-Fraenkel + Choice)

핵심 공리들 (직관적 설명):

  1. 외연 공리 (Extensionality):
     두 집합이 같은 원소를 가지면 같은 집합이다.
     → 집합은 원소에 의해서만 결정된다 (순서, 표현 무관)

  2. 공집합 공리: ∅가 존재한다.

  3. 짝 공리: a, b가 주어지면 {a, b}를 만들 수 있다.

  4. 합집합 공리: 집합들의 모임이 주어지면 합집합을 만들 수 있다.

  5. 멱집합 공리: A가 주어지면 P(A)를 만들 수 있다.

  6. 분리 공리 (Schema): 기존 집합에서 조건을 만족하는 원소만 골라낼 수 있다.
     → {x ∈ A | P(x)}는 OK. {x | P(x)}는 안 됨! (러셀의 역설 방지)
     → "이미 있는 집합에서 부분을 골라내는 것"만 허용

  7. 대체 공리 (Schema): 집합의 각 원소에 함수를 적용한 결과도 집합이다.

  8. 무한 공리: 무한 집합이 존재한다. (자연수 집합의 존재를 보장)

  9. 정칙성 공리: x ∈ x인 집합은 없다. (순환 방지)

  10. 선택 공리 (Axiom of Choice): 비어있지 않은 집합들의 모임에서
      각 집합의 원소를 하나씩 선택하는 함수가 존재한다.

왜 이렇게 복잡한가:
  러셀의 역설 같은 모순을 피하면서도
  수학에 필요한 모든 집합을 만들 수 있도록 균형을 잡는 것.
  
  핵심 전략: "무에서 집합을 만드는 것"을 금지하고
  "이미 있는 집합에서 새 집합을 만드는 규칙"만 허용.
```

## 3. 기수 — 무한의 크기를 비교하기

### 3.1 유한에서 무한으로

```
유한 집합의 크기 비교: 원소 수를 세면 된다.
무한 집합의 크기 비교: 원소를 "셀 수 없으므로" 다른 방법이 필요하다.

🔴 [정의] 두 집합 A, B의 크기가 같다 (|A| = |B|):
  A에서 B로의 전단사 함수(bijection)가 존재한다.

왜 전단사인가:
  일대일 대응이 있으면, 원소를 하나씩 짝지을 수 있다 = "같은 수"
  무한 집합에서도 이 정의가 작동한다!
```

### 3.2 셀 수 있는 무한 — ℵ₀

```
🔴 [정의] 셀 수 있다 (countable): ℕ과의 전단사가 존재
  = 원소를 a₁, a₂, a₃, ... 으로 번호 매길 수 있다

자연수 ℕ = {0, 1, 2, ...} — 가장 작은 무한 집합. 크기 = ℵ₀

놀라운 사실 — 짝수 집합도 ℵ₀:
  ℕ과 짝수 집합 사이의 전단사: n ↔ 2n
  0↔0, 1↔2, 2↔4, 3↔6, ...
  
  "부분이 전체와 같은 크기" — 이것이 무한의 특성이다.
  유한에서는 불가능하지만, 무한에서는 가능.

정수 ℤ도 ℵ₀:
  0, 1, -1, 2, -2, 3, -3, ... 으로 번호 매김

유리수 ℚ도 ℵ₀ (칸토어의 대각선 논법):
  유리수를 격자에 배열하고 대각선으로 순회하여 번호를 매긴다:
  
  1/1  1/2  1/3  1/4 ...
  2/1  2/2  2/3  2/4 ...
  3/1  3/2  3/3  ...
  
  대각선 순서: 1/1, 1/2, 2/1, 1/3, 2/2, 3/1, ...
  → 모든 유리수에 번호를 매길 수 있다 → 셀 수 있다
```

### 3.3 셀 수 없는 무한 — 칸토어의 혁명

```
🔴 [정리] 실수 ℝ은 셀 수 없다. |ℝ| > ℵ₀

칸토어의 대각선 논법 (1891):

  귀류법: ℝ이 셀 수 있다고 가정. 모든 실수를 나열:
  
  r₁ = 0. d₁₁ d₁₂ d₁₃ d₁₄ ...
  r₂ = 0. d₂₁ d₂₂ d₂₃ d₂₄ ...
  r₃ = 0. d₃₁ d₃₂ d₃₃ d₃₄ ...
  r₄ = 0. d₄₁ d₄₂ d₄₃ d₄₄ ...
  ...

  대각선 숫자: d₁₁, d₂₂, d₃₃, d₄₄, ...
  
  새 실수 s를 만든다:
    s의 n번째 자릿수 = (dₙₙ와 다른 숫자)
  
  s는 r₁과 첫째 자리가 다르고, r₂와 둘째 자리가 다르고, ...
  → s는 목록의 어떤 수와도 다르다!
  → 목록에 없는 실수가 존재 → 모순!
  
  따라서 ℝ은 셀 수 없다. □

의미:
  무한에도 "크기"가 있고, ℕ보다 ℝ이 "더 큰 무한"이다.
  ℵ₀ < 2^ℵ₀ = |ℝ| = 𝔠 (연속체의 크기)

🟢 [유도 가능] 칸토어 정리: |A| < |P(A)| (항상)
  어떤 집합이든, 그 멱집합이 더 크다.
  → 무한의 크기는 끝없이 올라간다: ℵ₀ < 2^ℵ₀ < 2^(2^ℵ₀) < ...

🔵 [CS 연결]
  대각선 논법은 정지 문제(Halting Problem)의 결정 불가능성 증명에도 사용된다:
    모든 프로그램을 열거하고, 대각선으로 "어떤 프로그램과도 다른" 것을 구성
    → 모순 → 정지 문제를 푸는 프로그램은 존재하지 않는다
    
  칸토어의 논법 = 튜링의 논법 — 같은 아이디어의 다른 적용
```

### 3.4 연속체 가설

```
🔴 [미해결/독립] 연속체 가설 (Continuum Hypothesis):
  ℵ₀ < |S| < 2^ℵ₀ 인 집합 S가 존재하는가?
  
  "자연수보다 크고 실수보다 작은 무한이 있는가?"

괴델(1940): ZFC와 모순되지 않는다 (참이어도 OK)
코헨(1963): ZFC에서 증명할 수 없다 (거짓이어도 OK)

→ ZFC 내에서 참도 거짓도 증명할 수 없다 = "독립"
→ 수학의 기초에 근본적 한계가 있음을 보여준다
```

## 4. 선택 공리 — 논쟁적이지만 필수적인 도구

```
🔴 선택 공리 (Axiom of Choice, AC):
  비어있지 않은 집합들의 모임에서,
  각 집합의 원소를 하나씩 선택하는 함수가 존재한다.

왜 논쟁적인가:
  유한이면 당연하다 (하나씩 고르면 됨).
  무한이면? "무한히 많은 선택을 동시에 할 수 있는가?"
  → 구성적으로 보여줄 수 없지만, 존재한다고 가정한다.

AC의 동치 명제들:
  - 초른의 보조정리 (Zorn's Lemma)
  - 정렬 원리: 모든 집합에 전순서를 줄 수 있다
  
🔵 [CS 연결]
  AC는 대부분의 CS에서 명시적으로 필요하지 않다.
  유한 대상만 다루는 알고리즘에서는 AC 없이도 충분하다.
  그러나 이론적 기초(예: 형식 의미론)에서 간접적으로 사용된다.
```

# Part B: 범주론 (Category Theory)

## 5. 왜 범주론인가 — "패턴의 패턴"

### 5.1 범주론이 태어난 이유

```
수학의 여러 분야에서 같은 패턴이 반복된다:

  집합 사이의 함수,
  군(group) 사이의 준동형사상,
  벡터 공간 사이의 선형 변환,
  위상 공간 사이의 연속 함수
  
  이 모두가 "대상(object)과 대상 사이의 화살표(morphism)"라는 
  동일한 구조를 가진다.

범주론 = 이 공통 구조 자체를 연구하는 학문
  → "구체적인 대상이 무엇인지"는 무시하고
    "대상들 사이의 관계(화살표)가 어떤 규칙을 따르는가"에 집중

왜 CS에서 중요한가:
  Haskell 등 함수형 언어의 핵심 개념(Functor, Monad)이 범주론에서 왔다.
  타입 시스템의 이론적 기반이 범주론이다.
  "디자인 패턴"의 수학적 일반화라고 볼 수 있다.
```

### 5.2 범주의 정의 — 가장 단순한 수학적 구조

```
🔴 [정의] 범주 C는 다음으로 구성된다:

  (1) 대상(object)의 모임: ob(C)
  (2) 사상(morphism, 화살표)의 모임: 각 대상 쌍 A, B에 대해 Hom(A, B)
  (3) 합성: f: A → B, g: B → C이면 g ∘ f: A → C
  (4) 항등 사상: 각 A에 대해 id_A: A → A

  규칙:
    결합법칙: h ∘ (g ∘ f) = (h ∘ g) ∘ f
    항등원:   f ∘ id_A = f = id_B ∘ f   (f: A → B일 때)

이것이 전부다. 대상이 무엇이고 화살표가 무엇인지는 지정하지 않는다.
```

**범주의 예시들:**

```
┌────────────┬────────────────┬─────────────────┬────────────┐
│ 범주        │ 대상            │ 사상             │ 합성        │
├────────────┼────────────────┼─────────────────┼────────────┤
│ Set        │ 집합            │ 함수             │ 함수 합성    │
│ Grp        │ 군              │ 군 준동형사상     │ 사상 합성    │
│ Vect       │ 벡터 공간       │ 선형 변환        │ 행렬 곱     │
│ Top        │ 위상 공간       │ 연속 함수        │ 함수 합성    │
│ Hask       │ Haskell 타입    │ 함수 a → b       │ 함수 합성    │
│ 프로그래밍  │ 타입            │ 프로그램/함수     │ 파이프라인   │
└────────────┴────────────────┴─────────────────┴────────────┘

범주론의 힘:
  이 모든 것에 동일한 이론이 적용된다.
  Set에서 증명한 것이 Vect에서도, Hask에서도 성립한다.
  (정확히는, 해당 범주가 필요한 성질을 가질 때)
```

## 6. 함자 (Functor) — 범주 사이의 번역기

```
🔴 [정의] 함자 F: C → D는 두 범주 사이의 "구조를 보존하는 대응":

  - 대상을 대상으로: C의 대상 A → D의 대상 F(A)
  - 사상을 사상으로: C의 f: A → B → D의 F(f): F(A) → F(B)
  
  규칙:
    F(id_A) = id_{F(A)}         (항등 보존)
    F(g ∘ f) = F(g) ∘ F(f)     (합성 보존)

직관: "구조를 유지하면서 한 세계에서 다른 세계로 번역한다"

🔵 [CS 연결 — 프로그래밍에서의 Functor]

  Haskell의 Functor:
    class Functor f where
      fmap :: (a -> b) -> f a -> f b
  
  f는 타입을 타입으로 보내고 (List, Maybe, IO 등),
  fmap은 함수를 함수로 보낸다.
  
  예시: List는 Functor이다
    List는 타입 a를 [a]로 보낸다 (대상의 대응)
    fmap은 (a → b) 함수를 ([a] → [b]) 함수로 보낸다 (사상의 대응)
    
    fmap (+1) [1, 2, 3] = [2, 3, 4]
    
    "리스트 안의 각 원소에 함수를 적용" = Functor의 fmap
  
  Maybe도 Functor이다:
    fmap (+1) (Just 5) = Just 6
    fmap (+1) Nothing  = Nothing
    
    "있으면 적용, 없으면 그대로" = 구조를 보존하면서 함수를 적용

왜 Functor 개념이 유용한가:
  다양한 "컨테이너"(List, Maybe, IO, Tree, ...)에 대해
  "안의 값에 함수를 적용한다"는 동일한 인터페이스를 제공한다.
  → 코드의 일반성과 재사용성을 높인다.
```

## 7. 자연 변환 (Natural Transformation)

```
🔴 [정의] 두 함자 F, G: C → D 사이의 자연 변환 η: F ⇒ G:

  C의 각 대상 A에 대해 η_A: F(A) → G(A) (D의 사상)가 있되,
  
  다음 다이어그램이 교환(commute)한다:
  
    F(A) ──η_A──→ G(A)
     │               │
    F(f)            G(f)
     │               │
     ▼               ▼
    F(B) ──η_B──→ G(B)
  
  즉: η_B ∘ F(f) = G(f) ∘ η_A  (어떤 경로든 같은 결과)

직관: "함자 F에서 함자 G로의 체계적인 변환"
  각 대상에서의 변환이 전체 구조와 일관되게(naturally) 작동한다.

🔵 [CS 연결]
  Haskell: 다형 함수(polymorphic function)가 자연 변환
  
  예: safeHead :: [a] -> Maybe a
      safeHead []    = Nothing
      safeHead (x:_) = Just x
  
  List에서 Maybe로의 자연 변환이다.
  어떤 타입 a에 대해서든 일관되게 작동한다.
```

## 8. 곱과 쌍대곱 — 보편적 구성

### 8.1 곱 (Product)

```
🔴 [정의] 범주 C에서 A와 B의 곱(product) A × B:
  
  투영 사상 π₁: A×B → A, π₂: A×B → B 가 존재하고,
  임의의 C에서 f: C → A, g: C → B가 있으면
  h: C → A×B가 유일하게 존재하여 π₁∘h = f, π₂∘h = g

     C
    ╱ │ ╲
   f  h  g
  ╱   │   ╲
 A ←─A×B─→ B
    π₁    π₂

직관: "두 정보를 묶는 가장 경제적인 방법"

🔵 [CS 연결]
  Set에서의 곱 = 카르테시안 곱 (순서쌍)
  프로그래밍에서 = 튜플, struct, pair, record
  
  (Int, String) = Int와 String의 곱 타입
  π₁ = fst,  π₂ = snd
```

### 8.2 쌍대곱 (Coproduct)

```
🔴 [정의] 곱의 "화살표를 뒤집은 것":
  
  삽입 사상 ι₁: A → A+B, ι₂: B → A+B 가 존재하고,
  임의의 C에서 f: A → C, g: B → C가 있으면
  h: A+B → C가 유일하게 존재하여 h∘ι₁ = f, h∘ι₂ = g

🔵 [CS 연결]
  Set에서 = 합집합 (disjoint union)
  프로그래밍에서 = 태그드 유니온, Either, enum, 대수적 데이터 타입
  
  Either Int String = Int 또는 String 중 하나
  Left 42 : Either Int String
  Right "hello" : Either Int String

곱 vs 쌍대곱:
  곱 = "A이면서 동시에 B" (AND) → 튜플, struct
  쌍대곱 = "A이거나 B" (OR) → Either, enum, union
  
  이것이 타입 이론에서 곱 타입(product type)과 합 타입(sum type)이라 불리는 이유.
```

## 9. 모나드 (Monad) — "계산의 효과"를 다루는 패턴

### 9.1 모나드란 — 왜 이것이 프로그래밍에서 중요한가

```
🔴 [정의] 범주 C 위의 모나드 M = (T, η, μ):
  
  T: C → C           함자 (타입을 감싼 타입으로)
  η: Id ⇒ T          unit/return (값을 감싸기)
  μ: T∘T ⇒ T         join (이중 감싸기를 풀기)
  
  규칙 (모나드 법칙):
    μ ∘ Tμ = μ ∘ μT           (결합법칙)
    μ ∘ Tη = μ ∘ ηT = id      (단위법칙)

이것이 추상적이므로, 프로그래밍에서의 의미를 먼저 보자:

🔵 [CS 연결 — Haskell의 Monad]

  class Monad m where
    return :: a -> m a              -- η (값을 감싸기)
    (>>=)  :: m a -> (a -> m b) -> m b  -- bind (연쇄 계산)

  (>>=)는 "앞 계산의 결과를 꺼내서 다음 계산에 전달"

왜 모나드가 필요한가:

  순수 함수형 언어에서는 부수 효과(side effect)가 없다.
  그런데 현실 프로그램은 효과가 필요하다:
    - 실패할 수 있는 계산 → Maybe 모나드
    - 여러 결과를 가질 수 있는 계산 → List 모나드
    - 입출력이 필요한 계산 → IO 모나드
    - 상태를 가지는 계산 → State 모나드

  모나드는 이런 "효과"를 타입 시스템 안에서 안전하게 다루는 패턴이다.
```

### 9.2 모나드 예시들

```
Maybe 모나드 — "실패할 수 있는 계산":

  return x = Just x
  Nothing >>= f = Nothing       -- 이미 실패했으면 전파
  (Just x) >>= f = f x          -- 성공했으면 다음 계산에 전달

  예시: 안전한 나눗셈 연쇄
    safeDivide x 0 = Nothing
    safeDivide x y = Just (x / y)
    
    result = Just 100 >>= (\x -> safeDivide x 5)
                      >>= (\y -> safeDivide y 2)
    -- Just 10.0
    
    result = Just 100 >>= (\x -> safeDivide x 0)
                      >>= (\y -> safeDivide y 2)
    -- Nothing  (중간에 실패하면 나머지 건너뜀)

  에러 처리를 if-null 체크 없이 깔끔하게!

List 모나드 — "여러 가능성":
  return x = [x]
  xs >>= f = concat (map f xs)  -- 각 원소에 f 적용 후 펼치기
  
  예시: 비결정적 계산
    [1,2,3] >>= (\x -> [x, x*10])
    -- [1, 10, 2, 20, 3, 30]

IO 모나드 — "현실 세계와의 상호작용":
  순수 함수형 언어에서 입출력을 다루는 유일한 방법
  IO 안에 "세계 상태"를 캡슐화하여 순수성 유지

모나드의 핵심 가치:
  다양한 "효과"를 하나의 통일된 인터페이스(return, >>=)로 다룬다.
  새로운 효과가 필요하면 새 모나드를 정의하면 된다.
  → "효과의 추상화" = 범주론의 모나드 개념이 프로그래밍에 적용된 것
```

## 10. 요네다 보조정리 — "대상은 관계에 의해 결정된다"

```
🔴 [정리] 요네다 보조정리 (Yoneda Lemma):
  대상 A는 "다른 모든 대상에서 A로 오는 사상의 패턴"에 의해 완전히 결정된다.

  형식적으로: Nat(Hom(A, -), F) ≅ F(A)
  
  "Hom(A,-)에서 F로의 자연 변환의 집합은 F(A)와 동형이다"

직관:
  "대상 자체가 무엇인지"는 모른다.
  그러나 "그 대상이 다른 대상들과 어떻게 관계하는지"를 완전히 알면,
  대상을 완전히 결정할 수 있다.
  
  비유: 사람을 "그 사람이 어떤 키워드인지"로 알 수 없지만,
       "그 사람과 다른 모든 사람의 관계"를 완전히 알면 그 사람을 특정할 수 있다.

🔵 [CS 연결]
  인터페이스 기반 프로그래밍:
    객체의 내부 구현은 모른다.
    그 객체가 어떤 메서드에 어떻게 반응하는지(= 다른 것들과의 관계)로 정의한다.
    → 요네다 보조정리의 프로그래밍적 표현
```

## 12. 정리

```
Part A — 집합론:
  [원리 1] 집합 = 수학의 기본 건축 자재. 모든 것을 집합으로 정의 가능.
  [원리 2] ZFC 공리 = 모순 없이 집합을 만드는 규칙.
  [원리 3] 기수 = 전단사로 비교. 무한에도 크기가 있다 (ℵ₀ < 2^ℵ₀).
  [원리 4] 대각선 논법 = "목록에 없는 것"을 구성하는 보편적 기법.

Part B — 범주론:
  [원리 5] 범주 = 대상 + 화살표 + 합성. 구조의 가장 추상적 표현.
  [원리 6] 함자 = 범주 사이의 구조 보존 대응 = 프로그래밍의 Functor.
  [원리 7] 모나드 = 효과를 캡슐화하는 패턴 = bind/return.
  [원리 8] 곱/쌍대곱 = AND/OR의 범주론적 표현 = 타입 시스템의 기반.

외워야 할 것:
  🔴 러셀의 역설 (자기 참조의 위험)
  🔴 ℵ₀ < 2^ℵ₀ (무한의 계층)
  🔴 범주의 정의 (대상, 사상, 합성, 항등)
  🔴 함자의 정의 (대상→대상, 사상→사상, 구조 보존)
  🔴 모나드의 프로그래밍적 의미 (return, >>=)

유도할 수 있는 것:
  🟢 ℝ의 비가산성 (대각선 논법)
  🟢 곱/쌍대곱 ↔ 튜플/Either 대응
  🟢 Maybe가 모나드임 (법칙 검증)
```
